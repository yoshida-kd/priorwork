# 各論文のカードを記入する

ルールは [AGENTS.md](../../../AGENTS.md) に従う。

## 深さによる違い

- `full`: **採用論文すべて**について本文を取得し（`./priorwork fulltext`）、本文から記入して確認レベルを「本文確認済」にする。「中核かどうか」で読む論文を選ばない。「要旨のみ」にしてよいのは、`fulltext` を試して本文が見つからなかった論文だけ（失敗は記録され、`check` が「試していない」と区別する）。
  - 本文は頭から全部を読まなくてよい。データ・サンプル、識別戦略、主な結果（表）、限界の節を重点的に読み、カードの欄を埋める。
- `quick`: 要旨だけで記入してよい（確認レベルは「要旨のみ」）。

どちらでも、要旨・本文に書かれていることだけを書き、確認レベルを必ず更新する。**「本文確認済」にするのは、`./priorwork fulltext` で取得した本文を読んで記入したときだけ。** 要旨から書いたカードは、本文がキャッシュにあっても「要旨のみ」にする。

原稿から作ったサーベイ（`priorwork-manuscript`）では、深さによらず、下書きで引用する論文は本文確認済にする（`check` が WARN を出す）。

## 手順（1 本ずつ、採用論文がなくなるまで）

1. 未記入の論文を確認する。Zotero のコレクションを結び付けていれば、そこに PDF がある論文から始める。

   ```bash
   ./priorwork status <survey>
   ./priorwork zotero <survey>     # Zotero 連携があれば、PDF の有無が分かる
   ```

2. 本文を取得する（Zotero の PDF → オープンアクセス版の順に探す）。

   ```bash
   ./priorwork fulltext <survey> <番号>
   ```

   取得できなければ要旨だけで記入し、確認レベルを「要旨のみ」にする。本文が取れなかった論文は、最後の報告で「Zotero に PDF を添付すれば本文で確かめられる」と伝える。

   取得元が「Zotero の索引テキスト（ページ区切りなし）」の場合、ページ番号は書かず「（ページ未確認）」とする。

   - 「PDF は N ページしかない」と出たら、出版社のプレビューなどで本文が欠けている。その本文でカードを書かず「要旨のみ」にし、報告で PDF の全体を Zotero に添付するよう頼む。
   - ページは掲載誌のページ（PDF の各ページに印刷された番号）で書く。著者最終稿（AAM）・原稿版など掲載誌のページが無い本文では、PDF のページ（`=== page N ===` の N）で書き、メモに「ページは AAM の PDF のページ」と書く。

3. サーベイ Markdown の「各論文の詳細」の節で、その論文のカード（`<!-- paper: ... -->` の下）の記入欄だけを書き換える（`./priorwork card <survey> <番号> --set rq=... evidence=fulltext` でもよい）。
   - **レポートの言語で書く**（日本語のレポートなら日本語）。要旨の英文を写さず、自分の言葉で要約する。用語の原語は括弧内に残す（例: 差の差（difference-in-differences））。
   - 見出し行・`書誌` 行・`⚠️` 行は自動生成されるので触らない。
   - `**RQ**: ` などの行内には、マトリクスに載る短い要約（1 文）を書く。詳細は直下に `  - ` の箇条書きで足す。
   - 本文に書かれていることだけを書く。$N$・推定値・期間は本文の表記どおりに書き、該当ページを `（p. 12）` のように添える。本文確認済のカードでは、データ・識別戦略・主な結果の欄に必ずページ（またはページ区切りが無い本文なら「（ページ未確認）」）を付ける。
   - 識別戦略は、その論文が実際に使った手法を書く（DID を使っていない論文に DID と書かない）。分からなければ「記載なし」。
   - 主な結果は、結論の向き（増える／減る、促す／促さない）を本文どおりに書く。
   - 見つからなければ「記載なし」と書く。推測で埋めない。
   - カードの中で別の論文やデータの出典を「著者 (年)」の形で書かない（`check` が未登録の引用として ERROR にする）。「Franchino の 2004 年のデータ」のように書く。
   - `**確認レベル**` を「本文確認済」または「要旨のみ」に更新する。
   - 本文を読んで範囲から外れると分かった論文は、カードを書かずに `./priorwork exclude` で理由を付けて除外する。

4. 数本ごとにマトリクスを更新し、検査する。`check` は本文に無い数値・論文に無いページ・ページの無いカード・レポートの言語でないカードを WARN にする。出たら本文と突き合わせて直す。

   ```bash
   ./priorwork render <survey>
   ./priorwork check <survey> --offline
   ```

相談モードのときだけ、2〜3 本ごとに要点（識別戦略・主な結果）を伝えて、続けるか確かめる。
