# Priorwork 手引き

> これは手引きの原稿。読むなら **<https://yoshida-kd.github.io/priorwork/ja/guide/>** で。 <!-- pages:skip -->

**社会科学と臨床研究の先行研究サーベイを、AI エージェントに任せて作る — ターミナルは不要**

Priorwork（prior work ＝ 先行研究）は、経済学・社会学・政治学・行政学・経営学・心理学などのテーマ別の先行研究サーベイを、AI エージェント（Claude Code・Antigravity など）に任せて作るための道具だ。テーマを伝えれば、エージェントが範囲を決め、文献を探して選び、論文カードを書き、サーベイの文章を書き、検査して読める形に書き出す。あなたは結果を読み、VS Code のサイドバーで確かめて直す。

この手引きは VS Code で使う人のためのもので、出てくるのはボタン・メニュー・エージェントへの頼み方だけだ。

- まだ入れていなければ: [Priorwork のインストール](https://yoshida-kd.github.io/priorwork/ja/install/)
- 急ぐなら: [クイックガイド](https://yoshida-kd.github.io/priorwork/ja/quickstart/)
- 自分の原稿から、Octavo と一緒に: [原稿から始める](https://yoshida-kd.github.io/priorwork/ja/manuscripts/)
- そのほかのすべて（エージェントが実行するコマンドの全部）は、AI エージェント向けに書いた[リファレンス](https://yoshida-kd.github.io/priorwork/ja/reference/)にある。この手引きにボタンのないことは、エージェントに頼む。

[English guide](https://yoshida-kd.github.io/priorwork/guide/)

## 1. はじめに

### 1.1 できること

- **任せる。** 「〇〇について先行研究をまとめて」と頼むだけで、エージェントが範囲の設定から書き出しまで進める。どこで止まって確かめを求めるか（標準・全自動・手動）は選べる。コマンドもスキル名も覚える必要はない。
- **自分の原稿から。** 形式を問わず、書きかけでも、原稿を渡すと 1 本のレポートを作る。どこに何を足すか、引用の点検、足りない先行研究、論の組み立てへのコメント（[詳しく](https://yoshida-kd.github.io/priorwork/ja/manuscripts/)）。
- **文献を探す。** Semantic Scholar で英語のキーワード検索（関連度順・ブール演算の bulk 検索）をし、DOI・掲載誌・ISSN を OpenAlex で照合する。採用した論文の参考文献と被引用をたどって、キーワード検索で漏れた論文も拾う。
- **論文カードを作る。** 採用した論文ごとに、RQ・説明変数・被説明変数・データ・識別戦略・結果・限界を記入したカードを作る。カードから比較マトリクスが自動で作られる。
- **でっち上げを検出する。** 文章中の「著者 (年)」が登録済みの論文に対応しているか、DOI が別の論文を指していないかを機械的に検査する。
- **読める形に書き出す。** 管理用の印や未記入の欄を除いた HTML（Word・Markdown も可）を作り、VS Code の中で見られる（SSH でつないだサーバーでも）。
- **確かめて直す。** 採否とその理由、カード、検索の記録はすべて残る。サイドバーの論文ごとのページで、採否を覆し、カードを直せる。

### 1.2 任せて、確かめる

エージェントは、範囲と採否を自分で決めて進める。ただし、決めたことには必ず理由を残し、範囲もレポートに書き込む。カードには要旨・本文に書かれていることだけを書き、何で確かめたか（確認レベル）を残す。あなたはそれを読んで、違うと思ったところを直す。直した採否やカードは、エージェントが次の作業で従う。

どこで止まって確かめを求めるかは選べる。標準では、範囲を決めたところと、カードを書く前（Zotero に論文を集めてもらうため）の 2 か所で止まる。止まらずに最後まで進める全自動と、工程ごとに止まる手動もある（[3.6](#36-進め方を選ぶ続きを頼む)）。検索や選別を自分でサイドバーから行うこともできる（[4](#4-自分で操作する)）。

拡張機能が自分で AI のサービスを呼ぶことはない。AI の手助けは、あなたがふだん使っているエージェントを通してだけ入る。

### 1.3 必要なもの

| もの | 要るか | 説明 |
| :--- | :--- | :--- |
| VS Code と Priorwork の拡張機能 | 必須 | Linux・macOS。Windows では WSL の中で使う（[インストール](https://yoshida-kd.github.io/priorwork/ja/install/#2-windows)） |
| AI エージェント | 必須 | Claude Code・Antigravity など、VS Code で動き `AGENTS.md` を読むもの |
| Python 3.10 以上 | 自動 | 無ければ拡張機能が uv を入れ、uv が Python を取ってくる |
| git と GitHub のアカウント | 推奨 | ワークスペースを GitHub の非公開リポジトリに置く |
| Semantic Scholar の API キー | 推奨 | 無料。無いと検索がレート制限で失敗しやすい |
| Zotero | 任意 | 採用論文を Zotero に集める、Zotero の PDF から本文を読む |
| SSCI 収録誌のリスト | 任意 | Clarivate の Master Journal List の CSV。無ければ主要誌から推定 |

## 2. ワークスペースを作る

**ワークスペース**は、サーベイのレポートとその状態を置くフォルダ。1つのワークスペースに、いくつでもサーベイを置ける。GitHub の非公開リポジトリで管理する。

### 2.1 作る

1. 空のフォルダを開くか、何も開いていない状態で、サイドバーの **ワークスペースを作る** を押す。
2. 場所と、レポートの言語（日本語・英語）を選ぶ。言語は後から変えられない。レポートの見出しと、エージェント向けの指示（`AGENTS.md` とスキル）がこの言語になる。
3. 拡張機能が `.venv` を作り、PyPI から `priorwork` を入れて、ワークスペースを用意する（`git init` も行う）。

### 2.2 設定する

サイドバーの歯車（**設定**）を開く。

1. **Semantic Scholar** に API キーを入れる。[ここから無料で申し込める](https://www.semanticscholar.org/product/api#api-key-form)。
2. Zotero を使うなら、**Zotero** の欄を埋める（[7.2](#72-zotero)）。
3. SSCI 収録誌のリストがあれば、**SSCI リスト（CSV）を取り込む…** で取り込む（[7.3](#73-ssci-収録誌のリスト)）。
4. **保存して接続を確かめる** を押すと、診断の結果がページの下に出る。
5. エージェントが `./priorwork` を実行するたびに確認を求めてこないよう、エージェントに `./priorwork` を許可する。
   - **いつ要るか**: エージェントに作業を任せるとき（チャットで頼むとき）だ。エージェントは検索・採否・カードの記入などのたびにターミナルで `./priorwork …` を実行し、1 つのサーベイで数十〜数百回になる。許可していないと、その都度「実行してよいか」と聞かれる。サイドバーのボタンや、あなたがターミナルで打つ `./priorwork` には要らない（エージェントを通らないため）。
   - **何を許すか**: `./priorwork` で始まるコマンドだけだ。Priorwork が触るのはワークスペースの中（`reports/`・`.priorwork/`）と文献の API だけで、Git は操作しない。Zotero に書き込むのは、あなたが許したときだけ（[7.2](#72-zotero)）。ほかのコマンドは今までどおり確認される。
   - **Claude Code**: 自動だ。ワークスペースを作ったとき（と `priorwork sync` のたび）に、`.claude/settings.json` の許可のルールへ `Bash(./priorwork:*)` が足される。ほかの設定はそのまま残る。やめたいときは、同じルールを `allow` から `deny` に移す（消すだけだと次の sync で足し直される。`deny` にあれば足さない）。
   - **Antigravity**: ワークスペースに置ける設定ファイルが無いため、自動にはできない。設定の、確認なしで実行してよいターミナルのコマンド（許可リスト）に `./priorwork` を一度だけ足す（メニューの名前は版によって違う）。ほかのコマンドは今までどおり確認される。

設定はワークスペースの `.env` に保存される。`.env` は Git に載らない。キーの値は設定のページに表示されない。

### 2.3 GitHub に置く

レポートと状態ファイルには論文の要旨が入るので、ワークスペースは**非公開**のリポジトリに置く。

1. サイドバーの **まだ GitHub にありません — 非公開リポジトリとして公開する** を押す。
2. VS Code に聞かれたら **Publish to GitHub private repository**（非公開）を選び、示されたファイルをすべて含める（`.env` は `.gitignore` で除かれている）。

エージェントは、サーベイ名のブランチ（例: `20261015_statutory_text_analysis`）を作って工程ごとにコミット・push し、書き出しまで済んだら PR を作る。**マージはしない。** PR を見て、よければ GitHub でマージする。main への push・force push・マージは、Claude Code では `.claude/settings.json` の deny でも止めている。Git を使わせたくなければ `AGENTS.local.md` にそう書く。

### 2.4 別のマシンで続ける

1. VS Code でリポジトリを clone して開く。
2. サイドバーのメニュー（…）の **Python の環境（.venv）を用意する** を実行する。
3. **設定** でキーを入れ直す（`.env` は Git に載らないため）。SSCI リストも取り込み直す。

## 3. AI に任せる

### 3.1 頼む

ワークスペースのフォルダを開いたまま、エージェントのチャットで頼む。どちらの方法でも同じだ。

- **チャットで普通の言葉で頼む。** 例:「行政需要の変化に対して行政組織がどう人材を確保するか、make or buy の観点で先行研究を full でまとめて」。コマンドやスキル名を打つ必要はない（`/priorwork` と打っても構わない）。
- **サイドバーから頼む。** **新しいサーベイ** → **エージェントに任せる** で、テーマ（自由な言葉で）・深さ・進め方を選ぶと、依頼文がコピーされる。通知の **Claude Code を開く** などでチャットを開き、貼る。

リサーチクエスチョン・期間・採否の基準が決まっていれば、依頼に添える。無ければエージェントがテーマから決め、標準の進め方では、決めた範囲を示して確かめを求める（全自動なら最後の報告で「こう決めた」と伝える）。

### 3.2 エージェントがすること

エージェントは、ワークスペースの `AGENTS.md` とスキルに従い、次の順に進める。⏸ は標準の進め方で止まって確かめを求めるところ（[3.6](#36-進め方を選ぶ続きを頼む)）。

```
① 範囲を決める ⏸ → ② 検索 → ③ 選別 → ④ 引用をたどる → ⏸ Zotero に集める
  → ⑤ カードを記入 → ⑥ 文章 → ⑦ 検査と書き出し
```

1. **範囲**: リサーチクエスチョン・期間・分野・採用基準・除外基準・深さを決め、サーベイを作る。
2. **検索**: テーマをサブテーマに分け、英語のクエリで検索する。0 件のクエリは言い換える。
3. **選別**: 候補を採用基準・除外基準に照らして、採用・保留・除外に分ける。どれにも理由を残す。
4. **引用をたどる**: 採用論文の参考文献と被引用から、キーワード検索で漏れた論文を拾って選別する。標準の進め方では、ここで止まって Zotero に入れる DOI の一覧を示す（[3.7](#37-zotero-に集める)）。論文と PDF を Zotero に集めてから「続きをやって」と頼むと、カードを本文から書ける。
5. **カード**: 採用論文の本文（Zotero の PDF かオープンアクセス版）か要旨から、カードを記入する。
6. **文章**: カードをもとに、背景、先行研究の理論・手法・論争・空白（主張ごとに採用論文を引く）と、それとは分けて本研究の仮説と示唆を書く。
7. **検査と書き出し**: 引用・DOI・未記入の欄・カードと本文の食い違いを検査して直し、読むための版（HTML）を書き出す。
終わると、検索と採用の件数、自分で決めた範囲、残った注意点、Zotero に未登録の採用論文の数、レポートの見方を報告する。論文は `#232` のような番号ではなく「Goldschlag & Tabarrok (2018)」のように著者 (年) で示す。長い作業になるので、途中で「いまどこまで進んだか」を一行ずつ伝えることがある（止まる場所以外では答えを待たない）。

**監査（任意）。** 別のモデルにも確かめさせたいときは、そのモデル（例: Gemini が書いたなら Claude）のチャットで「サーベイ <名前> を監査して」と頼む（**エージェントに頼む… → 別のモデルとして監査する** でも依頼文をコピーできる）。同じモデルは自分の誤読に気付きにくいためだ。監査するモデルは、カードをすべて本文と突き合わせ、引用の向き・先行研究のように書かれた仮説・除外された論文を確かめて直し、監査を記録する（サーベイを書いたモデルは監査できない）。監査はしなくても、サーベイは未完成にならない。

### 3.3 深さ

**深さ**はサーベイの規模の目安だ。依頼に「quick」「さっと」「full」「網羅的に」などとあればそれに、無ければテーマの広さからエージェントが決める。

| | quick（簡易） | full（本格） |
| :--- | :--- | :--- |
| 向くテーマ | 狭い・概観だけ欲しい | 広い・サブテーマがある・網羅性が要る |
| 検索 | 2〜3 クエリ（1 回 10 件） | サブテーマごとに 2〜4 クエリ（1 回 25 件）、候補 100 本以上が目安 |
| 引用をたどる | 任意 | 行う |
| カード | 要旨のみでよい | 採用論文すべてを本文で確かめる（本文が見つからないものだけ要旨のみ） |
| 文章 | 概観と比較表 | 背景・学説・論争点・研究の空白まで |

full なのに検索が足りないと、サイドバーの **次にやること** に **検索を足す** が出る。エージェントもこれを見て検索を足す。

### 3.4 レポートを見る

読むための版（HTML）は、VS Code の中で開く。SSH でつないだサーバーでも、そのまま見られる。

- サイドバーでサーベイを右クリック → **レポートを書き出して見る**。
- エクスプローラーで `reports/<名前>.html` を右クリック → **Priorwork でレポートを見る**。
- エージェントが書き出したときは、通知の **見る** でも開ける。

文章は選択してコピーでき、**Ctrl+F**（Mac は **Cmd+F**）でページ内を検索できる。

未記入・未確認のカードや検査の ERROR が残っていると、冒頭に「下書き」と出る。ブラウザで開いて PDF に印刷することもできる（ローカルのマシンのとき）。

### 3.5 確かめて直す

サイドバーのサーベイの下に、採用・保留・除外・未選別の論文が並ぶ。論文を押すと、論文ごとのページが開く。

- **採否を確かめる**: 要旨と、エージェントが残した理由を見る。違うと思えば **I** 採用、**M** 保留、**X** 除外（理由つき）で覆す。複数の論文は、サイドバーで選んで右クリックからまとめて変えられる。
- **カードを確かめる**: 採用論文のページで、カードを要旨と見比べ、直して **Ctrl+S** で保存する。
- **範囲を直す**: サーベイの右クリックの **調査範囲を編集** で、リサーチクエスチョン・基準・深さを変える。

エージェントは、あなたが下した採否と直したカードを覆さない。直したあとで「続けて」と頼めば、それに合わせて進める。

### 3.6 進め方を選ぶ・続きを頼む

**進め方**は、エージェントがどこで止まってあなたの確かめを待つかだ。

| 進め方 | 止まるところ | 頼み方 |
| :--- | :--- | :--- |
| **標準**（既定） | 範囲を決めたところと、カードを書く前（Zotero に論文を集めてもらうため）の 2 か所 | 何も言わなければこれ |
| **全自動** | 止まらずに最後まで進める | 「全自動で」「最後まで止まらずに」 |
| **手動** | 工程ごと（範囲・検索・選別・引用・Zotero・カード・文章・検査）。採否も推薦を示して答えを待つ | 「相談しながら」「1 件ずつ見せて」 |

標準をすすめるのは、カードを書く前に採用論文を Zotero に集めて PDF をそろえると、エージェントが本文で確かめたカードが増え、結果として手間が減るからだ。止まる場所以外では、エージェントは理由を残しながら自分で判断する。

進め方はサーベイに記録され、次の会話でも同じ進め方で続く。いつも同じにしたいなら、ワークスペースの `AGENTS.local.md` に「進め方は全自動」などと書いておく。サイドバーの **新しいサーベイ → エージェントに任せる** でも選べる。

- **続き**: チャットで「続きをやって」「もっと検索して」「カードを埋めて」などと頼む。止まっていたところで「続きをやって」と言えば、確かめ終えた合図になる。サーベイの右クリックの **エージェントに頼む…** でも、よく頼む作業（続きを進める・最後まで進める・検索を足す・選別・引用をたどる・カードの記入・文章・検査と修正・別のモデルとしての監査）の依頼文をコピーできる。

- **やり直す**: 「このサーベイをやり直して」と頼むと、エージェントは同じ slug で新しいサーベイを作り、Priorwork が日付の直後に版を振る（`20261012_v2_<slug>`。サイドバーには **v2** と出る）。同じテーマのサーベイが並ぶときは、サイドバーに名前と日付も出る。古いほうが要らなくなったら、右クリックの **サーベイをアーカイブする…**（またはエージェントに頼む）で一覧から外す。いちばん下の **アーカイブ** にまとまり、何も消えない。戻すときはそこのボタンを押す。

会話を再開したときも「続きをやろう」と言えば、エージェントが状態を確かめて次の作業に進む。

### 3.7 Zotero に集める

論文を Zotero に入れるのはあなた（Priorwork に任せることもできる。下の「Priorwork に入れさせる」）。その手間を減らす方法が2つある（Zotero 連携の設定は [7.2](#72-zotero)）。

**採用論文の DOI をまとめて Zotero に入れる。**

1. Zotero で、論文を入れたいコレクション（フォルダ）を選んでおく。
2. サイドバーの次にやることの **Zotero に追加** を押し、**DOI をコピー** する（エージェントに「Zotero に入れたいので DOI の一覧をちょうだい」と頼んでも構わない）。
3. Zotero の **識別子でアイテムを追加**（魔法の杖）に貼って Enter を押す。選んでいたコレクションに入る。
4. **Zotero から読み直す** を押すと、登録状況が更新される。

標準の進め方では、エージェントがカードを書く前に止まって、この DOI の一覧を示す。サイドバーの次にやることにも **ここで止まってユーザーを待つ** が出て、押すと DOI のコピーと、エージェントへの「続きをやって」の依頼文のコピーができる。Zotero の連携を設定していなくても、DOI の一覧は出せる（採用論文すべて）。

**Priorwork に入れさせる。** 設定で許し（[7.2](#72-zotero)）、サーベイにコレクションを結び付けておけば（下）、Priorwork が採用論文をそのコレクションに入れる。

- ライブラリに同じ論文（DOI、無ければタイトルが同じもの）があれば、そのアイテムをコレクションに足す。無ければ書誌から新しく作る。あなたのアイテムを書き換えたり消したりはせず、ほかのコレクションにも触らず、コレクションも作らない。
- 次にやることの **コレクション「…」に入れる** を押すと、入れるものの一覧が出て、確かめてから入れる。エージェントも同じで、標準の進め方ではカードの前に止まるところで一覧を示し、あなたが了解したら入れる。全自動では止まらずに入れ、手動ではそのつど聞く。
- PDF は付かない。Zotero で選んで右クリック →「Find Full Text」（PDF を探す）でそろえる。
- **Priorwork が入れたものを取り消す…**（またはエージェントに「取り消して」）で、Priorwork が書いたものだけを戻す。作ったアイテムは Zotero のごみ箱に入れる（その後に手を入れたり、ファイルを添付したりしたものは残す）。もとからライブラリにあったアイテムは、コレクションから外すだけだ。

**Zotero のコレクションをサーベイに結び付ける。** サイドバーの各サーベイの下にある **Zotero のコレクションを結び付ける…** を押し、Zotero で作ったコレクションを選ぶ（Zotero の連携を設定していなければ **Zotero: 未設定** と出て、押すと設定のページが開く）。Priorwork はコレクションを作らないので、新しいコレクションは Zotero で作り（「マイライブラリ」を右クリック →「新しいコレクション…」）、一覧の **一覧を読み直す** で出す。一覧は Zotero と同じ木の形で並ぶ。下のコレクションに入れた論文も、そのコレクションの論文として数える（同じ名前のコレクションが別の親の下にあれば、パス `親 / 子` で区別する）。結び付けると、その行は **Zotero: <コレクション名>** になり、押すと変更・解除できる（エージェントに「Zotero の『〇〇』コレクションを使って」と伝えても構わない）。結び付けると:

- 「Zotero にあるか」は、そのコレクションに入っているかで判定する。
- コレクションに自分で入れた論文を、サーベイの候補に取り込める（次にやることの **Zotero のコレクションの … 本を候補に登録する**）。エージェントは、範囲から明らかに外れない限り採用する。
- 本文は、そのコレクションの PDF を優先して読む。

### 3.8 サーベイから短い文章を作る

講義資料・読書メモ・要点の整理など、サーベイを元にした短い文章も頼める（「この先行研究で、行政学の講義資料を 3 部構成の箇条書きで約 2000 字で」など）。エージェントは用途・字数・構成を記録し、`reports/<名前>.<文章の名前>.md` に書く。サーベイのファイルと並ぶので、Git にも一緒に入る。

- 引く論文は、採用論文のうち本文確認済のカードのものから選び、数値と結論の向きをカードの主な結果と照合する。
- 字数は、引用の括弧（「（Dell 2010）」）を含めずに数えるのが既定（含めるならそう頼む）。
- 末尾の参考文献は、引いた論文から自動で作られる。
- **サーベイを検査** は、採用論文に無い引用（ERROR）、本文確認済でないカードからの引用と、カードに無い数値（WARN）、目安から外れた字数（INFO）を知らせる。
- 読むための版は `reports/<名前>.<文章の名前>.html`（頼めば Word も）。

### 3.9 医学のサーベイ

臨床研究なら、頼むときにそう言う（「〇〇の臨床エビデンスのレビューを」）か、**新しいサーベイ** で **医学（臨床研究）** を選ぶ。するとサーベイは次のようになる。

- Semantic Scholar に加えて PubMed も検索し、レター・論説・コメントを除く
- 論文ごとに、研究デザインと、PubMed で MEDLINE に索引されているかを示す
- カードは臨床上の問い・対象集団・介入または曝露・アウトカム・研究デザイン・効果量を聞く
- レポートは、研究デザイン別のエビデンス・効果・安全性と有害事象の節を持つ
- 撤回された論文に印を付け、採用したままでは検査を通さない
- 公開された本文を PMC から読む

これは **叙述的レビュー** である。エージェント 1 人のスクリーニングはシステマティックレビューや PRISMA の基準を満たさず、レポートにもそう書かれる。診療指針でもない。医中誌 Web・Embase・CENTRAL は検索しない。

任意で **設定** から、無料の NCBI キーで PubMed を速くし、Master Journal List の SCIE リストで ✅ SCIE を足せる。2 種類のサーベイは 1 つのワークスペースに同居できる。

### 3.10 いくつものサーベイを同時に進める

別のサーベイの作業中に新しいサーベイを始めるなら、そう頼む（「別のサーベイが進行中なので、専用のフォルダで始めて」）。エージェントは、開いているサーベイに触らずに、`worktrees/` の下にそのサーベイのブランチのフォルダを作る。キー・雑誌のリスト・取得した本文は共有される。

そうしたサーベイはサイドバーに出る。押すとそのフォルダが新しいウィンドウで開くので、そこで続ける。PR をマージしたら、フォルダを消すようエージェントに頼む。コミットと push が済んでいないものがあれば断る。

## 4. 自分で操作する

エージェントに任せずに、サイドバーから自分で進めることもできる。サイドバーのサーベイの下にある **次にやること** が、いま何をすればよいかを示す。項目を押すと、その操作が始まる。

### 4.1 範囲を決める

**新しいサーベイ** → **自分で作る** で、テーマ・英語のスラッグ（ファイル名になる。例: `minimum_wage_employment`）・深さ・リサーチクエスチョンを入れる。期間・分野・採用基準・除外基準は、サーベイの右クリックの **調査範囲を編集** で後から足せる。採用基準・除外基準は、論文のページの上に表示される。

### 4.2 検索

**検索** に英語のクエリを入れ、検索の仕方を選ぶ。

- **検索**: Semantic Scholar の関連度検索（20件）。
- **Bulk 検索**: `+`（AND）、`|`（OR）、`-`（除外）、`"フレーズ"` が使え、被引用数の多い順（25件）。キーワード検索で埋もれる定番論文を拾える。`AND`・`OR`・`NOT` と書いても、それぞれ `+`・`|`・`-` に直す。
- **SSCI 収録誌のみ**: 関連度検索のうち SSCI 収録誌のものだけ。

結果は候補として登録される。同じ論文の WP 版と掲載版が両方あれば、掲載版だけを残す。書籍・WP・プレプリント・掲載誌不明のものは、既定で除かれる。DOI がすでに分かっている論文は **DOI を指定して追加** で登録できる。

特定の誌だけで探すときは、エージェントに頼む（「JPART と PAR だけで探して」）。誌で絞った検索は Semantic Scholar と OpenAlex の両方で探す。Semantic Scholar は論文の誌名を持たないことが多く、そこだけで探すと、その論文が黙って落ちる（分野で最もよく引かれる論文のこともある）。OpenAlex は誌を ID で選ぶので、それを拾える。OpenAlex から足した件数は、お知らせに出る。

### 4.3 選別

**候補を選別する** で、最初の未選別の論文のページが開く。

- 上にサーベイの採用基準・除外基準、その下にタイトル・著者・掲載誌と SSCI の判定・被引用数・警告・要旨が出る。
- **I** 採用、**M** 保留、**X** 除外（先に理由を入れる）、**U** 候補に戻す。決めると次の未選別の論文に進む（設定 `priorwork.autoAdvance`）。
- **N** 次の未選別、**J / K** 次 / 前、**O** DOI をブラウザで開く。
- よく使った除外の理由は、ボタンで選べる。

警告（⚠️）の付いた論文は、採用する前に確かめる。

| 警告 | 意味 |
| :--- | :--- |
| DOI が別タイトルを指している | Semantic Scholar の DOI が別の論文（リプライなど）のもの |
| DOI は WP / プレプリント版 | 掲載誌は示されているが、DOI は SSRN などの版 |
| OpenAlex に DOI が見つからない / DOI なし / DOI 未照合 | DOI の誤り、欠落、または照合できなかった |
| 書評・コメントの可能性 | 「…, by 著者名」の形のタイトル、または 1 ページだけ |

Semantic Scholar が雑誌の論文にプレプリントや WP の DOI を付けているときは、題名で OpenAlex を引き、雑誌版が一致すれば（同じ題名で、年の差が 2 年以内）その DOI と書誌情報に替える。そのときは警告の代わりに、元の DOI を書いた注記（ℹ️）が付く。

### 4.4 引用をたどる

**引用をたどる（スナウボール）** は、採用した論文の参考文献と被引用論文を OpenAlex から集め、採用論文の何本と引用関係にあるかの多い順に候補として登録する。採用論文が 3 本以上なら、既定では 2 本以上とつながるものだけを候補にする。登録された候補は、5.3 と同じように選別する。

### 4.5 論文カードを記入する

採用した論文には、レポートの「各論文の詳細」の節にカードが作られる。論文のページでカードを書き、**Ctrl+S** で保存する。本文は **本文を取得** で取り込める（[5.3](#53-本文の取得)）。記入だけをエージェントに頼むなら、**エージェントに頼む… → 論文カードを記入する** だ。カードについては[5](#5-論文カード)で詳しく説明する。

### 4.6 文章を書く

レポートは、まとめが先だ。背景（1章）、先行研究の理論的潮流・実証手法の変遷・合意と論争・研究の空白（2〜5章。主張ごとに採用論文を引く）、先行研究と分けた本研究の仮説と示唆（6章）のあとに、比較マトリクス・各論文の詳細・参照文献が続く。これらの節はカードをもとに書く文章で、見出しの下に「書く内容」の指示がある（0.1.5 までに作ったレポートは以前の並びのままだ）。Mermaid の図（```` ```mermaid ````）は HTML では図として表示される。サーベイの **作業用のレポート（Markdown）を開く** で開いて書く。エージェントに頼むなら **エージェントに頼む… → レポートの文章を書く** だ。

### 4.7 検査と書き出し

1. **サーベイを検査** を押すと、問題が VS Code の **問題** パネルに並ぶ（[6](#6-検査)）。
2. **レポートを書き出して見る** で、読むための版（HTML）が開く（[3.4](#34-レポートを見る)）。

## 5. 論文カード

### 5.1 欄

```
### #1 Acemoğlu et al. (2001): The Colonial Origins of Comparative Development
- 書誌: American Economic Review 91(5) | ✅ SSCI収録 | 被引用数 8534 | DOI   ← 自動
- 確認レベル: 未確認 / 要旨のみ / 本文確認済
- RQ: 制度は国家間の所得格差に因果的な影響を与えているか
- X（説明変数・介入）: 現代の制度の質
- Y（被説明変数・成果）: 1995年の1人当たりGDP
- データ・サンプル: 旧植民地64カ国
- 識別戦略: 2SLS。入植者の死亡率を操作変数に使う
- 主な結果: 制度の質は所得を大きく高める
- 限界: 死亡率データの測定誤差
- メモ:
```

- 見出しと書誌の行は自動で作られる。手で書くのは確認レベルからメモまでだ。
- 各欄の**1行目**は比較マトリクスに載るので、短く 1 文で書く。詳しいことは2行目以降に書くと、直下の箇条書きになる。
- 要旨・本文に書かれていることだけを書く。書かれていなければ「記載なし」と書く。
- カードはレポートの言語で書く。用語の原語は括弧内に残す。
- 本文確認済のカードでは、データ・識別戦略・主な結果にページ（`（p. 12）`）を添える。本文にページ区切りが無ければ「（ページ未確認）」と書く。

### 5.2 確認レベル

| 確認レベル | 意味 |
| :--- | :--- |
| 未確認 | まだ確かめていない（記入前、または推測が混じる） |
| 要旨のみ | 要旨で確かめた |
| 本文確認済 | **本文を取得**（`fulltext`）した本文で確かめた |

未確認のカードは検査で警告され、書き出しは「下書き」になる。full のサーベイでは、採用論文すべてを本文で確かめる。「要旨のみ」のままにできるのは本文が見つからなかった論文だけで、検査がその一覧を出すので、Zotero に PDF を添付すれば読める。

### 5.3 本文の取得

採用論文のページの **本文を取得** か、サイドバーの論文の右クリックで取得する（エージェントも同じ方法で取得する）。PDF はワークスペースに置かず、抽出したテキストだけを `.priorwork/cache/fulltext/`（Git 管理外）に残す。次の順に探す。

1. このマシンの Zotero の添付 PDF（DOI で照合）
2. Zotero Web API で見つけた添付 PDF（WebDAV、または Zotero のファイル同期）。サーベイに結び付けたコレクションのものを優先
3. Zotero が索引化した本文テキスト（ページ区切りが無い予備）
4. オープンアクセス版の PDF（OpenAlex が知っている所在をすべて試す。機関リポジトリなどのランディングページは、その中の PDF のリンクをたどる）

出版社のサイトは自動のダウンロードを拒むことが多いので、オープンアクセスでない論文は Zotero に PDF を添付してから取得する。

### 5.4 採用を取り消したとき

採用を取り消した論文のカードは、記入内容ごと状態ファイルに退避され、もう一度採用すると戻る。

## 6. 検査

**サーベイを検査** は次を調べる。

| 検査 | レベル |
| :--- | :--- |
| 文章・カード中の「著者 (年)」「(著者, 年; 著者, 年)」が登録済みの論文に対応しているか | ERROR（未登録）/ WARN（未採用） |
| 2001a / 2001b の区別が参照文献と合っているか | WARN |
| 文章中の DOI が登録済みか | ERROR |
| 採用論文の ⚠️、OpenAlex での DOI とタイトルの一致 | ERROR |
| カードの確認レベルと未記入の欄 | WARN |
| 本文確認済のカード: 本文に無い数値、論文に無いページ、ページが無い、本文を取得していない | WARN |
| レポートの言語で書かれていないカード | WARN |
| 論文を引いていないまとめの節（理論・手法・論争・空白）、本文に書いた採用数の食い違い | WARN |
| Zotero に無い採用論文 | WARN |
| レポートが状態ファイルと一致しているか | WARN |
| 未選別の候補、SSCI 以外の採用論文、組織名・図表番号とみなした引用 | INFO |

引用の検出は正規表現によるもので、すべての書き方を拾うわけではない。`Acemoglu et al. (2001, 2005)`、`Dell (2010, p. 5)`、`(e.g., Dell 2010; Acemoglu et al., 2001a)` は検出する。「World Bank (2010)」「OECD (2019)」のような組織名は INFO で伝える。論文ではないのに引用と誤認されたものは、レポートに次のコメントを書くと外せる。

```markdown
<!-- priorwork:ignore-citation Smith (2015) -->
```

## 7. 設定

### 7.1 API キー

| 設定 | 用途 |
| :--- | :--- |
| Semantic Scholar の API キー | 推奨。無いと検索がレート制限（HTTP 429）で失敗しやすい |
| OpenAlex の API キー・メールアドレス | 任意。OpenAlex はキーが無くても使えるが、1日の利用量に上限がある |

### 7.2 Zotero

設定すると、採用論文が Zotero にあるかの確認、コレクションとの結び付け（[3.7](#37-zotero-に集める)）、Zotero に添付した PDF からの本文の取得ができる。既定では読むだけで、Zotero にも WebDAV にも書き込みはしない。

1. <https://www.zotero.org/settings/keys> で API キーを作る。権限は **Allow library access だけ**にする（notes・write は外す）。同じページの「Your user ID for use in API calls」がユーザー ID だ。
2. 設定の **Zotero** にキーとユーザー ID を入れる。このマシンで Zotero を使っているなら、データフォルダ（既定 `~/Zotero`）も入れる。
   - **Priorwork に採用論文をサーベイのコレクションに入れさせる**なら（[3.7](#37-zotero-に集める)）、**Priorwork が採用論文をサーベイのコレクションに入れてよい**（`.env` の `ZOTERO_WRITE=1`）にチェックを入れ、Zotero のページでキーの **Allow write access** にもチェックを入れる。両方が要る。キーで書き込めるかは **保存して接続を確かめる** で分かる。
3. ファイル同期に WebDAV（Nextcloud など）を使っているなら、**Zotero のファイル同期（WebDAV）** に、PDF の zip が置かれたフォルダの URL（Zotero に設定した URL ＋ `zotero/`）・ユーザー名・パスワードを入れる。Nextcloud なら、`zotero` フォルダを閲覧のみで専用のユーザーに共有し、そのユーザーのアプリパスワードを使うと安全だ。
4. **保存して接続を確かめる** で確かめる。

WebDAV が「フォルダが見つかりません」になるときは URL を見直す。Nextcloud をサブパスに置いているなら、そのパスも含める（例: `https://example.com/nextcloud/remote.php/dav/files/<ユーザー名>/zotero/`）。

### 7.3 SSCI 収録誌のリスト

SSCI に収録されているかは、Clarivate の [Master Journal List](https://mjl.clarivate.com/) でしか確定できない。そこで SSCI のリストを CSV でダウンロードし（無料のアカウントが要る）、設定の **SSCI リスト（CSV）を取り込む…** で取り込む。リストはワークスペースの `.priorwork/data/` にコピーされ、ライセンスの都合で Git には載らない。リストが無ければ、主要誌約100誌の内蔵リストから推定する。

| 表示 | 意味 |
| :--- | :--- |
| ✅ SSCI収録（リスト照合済） | リストと ISSN または誌名が一致 |
| 🟡 SSCI収録の可能性大（誌名推定・要確認） | リストが無く、内蔵リストと一致 |
| 🔍 学術誌（SSCI未確認） / ⚪ SSCI非収録誌 | SSCI か分からない / リストに無い |
| 📕 書籍 / ❌ WP・プレプリント / ❓ 掲載誌不明 | 既定で検索結果から除く |

医学のサーベイには、同じサイトの SCIE リストを同じように取り込める（**SCIE リスト（CSV）を取り込む…**）。✅ SCIE が加わる。無ければ、雑誌は論文ごとの PubMed の記録で判定する。

### 7.4 VS Code の設定

## 8. エージェントへの指示

### 8.1 AGENTS.md とスキル

ワークスペースには、エージェント向けの指示（`AGENTS.md`）と、工程ごとのスキル（`.agent/skills/`。`.claude/skills/` からも見える）が入っている。入口は `priorwork` スキルで、状態を見て次の工程のスキル（`priorwork-new`・`priorwork-screen`・`priorwork-snowball`・`priorwork-extract`・`priorwork-check`）に進む。原稿から始めるときは `priorwork-manuscript`（[原稿から始める](https://yoshida-kd.github.io/priorwork/ja/manuscripts/)）を使う。エージェントは依頼の言葉からこれらを選ぶので、名前を覚える必要はない。

このワークスペースだけの指示（優先する分野・文体・除外したい誌名・「進め方は全自動」など）は `AGENTS.local.md` に書く。`AGENTS.md` とスキルはエンジンの版に合わせて書き換えられるので、直接編集しない。

### 8.2 エージェントが守ること

- 採否と範囲には理由を残し、あなたが下した判断を覆さない。
- 進め方の止まる場所で止まり、それ以外では自分で判断して進める。
- 報告では、論文を番号ではなく「著者 (年)」で示す。
- 文章で触れる論文はすべて登録済みのもの。記憶だけで著者・年・DOI を書かない。
- カードには要旨・本文に書かれていることだけを書き、確認レベルを更新する。
- ⚠️ の付いた論文は掲載版に置き換えるか、保留にして伝える。🟡（誌名推定）を「SSCI 収録」と断定しない。
- 完成と言う前に検査を通す。
- Priorwork 本体（`.venv` の中）のファイルを開かない。
- Zotero に書き込むのは、あなたが許したときに採用論文をサーベイのコレクションに入れるときだけ。Git はサーベイ名のブランチでコミット・push して PR を作るところまで。マージはあなたがする。

## 9. ワークスペースの中身

```text
my-surveys/
├── reports/                 # レポート（作業用の .md と、書き出した .html・原稿の下書き .draft.md など）
├── manuscripts/             # 原稿から始めるときの原稿と結果の表（論文ごとのフォルダ。読むだけ）
├── AGENTS.md, CLAUDE.md     # エージェント向けの指示（自動で更新。直接編集しない）
├── AGENTS.local.md          # このワークスペースだけの指示（自由に編集）
├── .agent/skills/           # 工程ごとのスキル（.claude/skills からも見える）
├── priorwork                # ./priorwork（エージェントが使う）
├── requirements.txt         # エンジンの版（priorwork==X.Y.Z）
├── .env                     # 設定（Git に載らない）
└── .priorwork/
    ├── config.json          # ワークスペースの言語
    ├── surveys/             # サーベイの状態（Git に載る）
    ├── cache/               # 本文テキスト・Zotero の一覧（Git に載らない）
    └── data/                # SSCI リスト（Git に載らない）
```

| ファイル | 中身 | 編集 |
| :--- | :--- | :--- |
| `reports/YYYYMMDD_<slug>.md` | 作業用のレポート（やり直した版は `YYYYMMDD_v2_<slug>.md`） | 文章とカードの記入欄はエージェント（または手）で書く。`<!-- BEGIN priorwork:… -->` 〜 `<!-- END priorwork:… -->` は自動で作り直される |
| `.priorwork/surveys/YYYYMMDD_<slug>.json` | 候補・採否と理由（履歴つき）・検索の記録・範囲・深さ・Zotero のコレクション | Priorwork だけが書き換える |

参照文献は採用論文から DOI つきで作られ、付録には検索・件数・除外の理由・見直した採否の記録が残る。

## 10. エンジンを更新する

ワークスペースは `requirements.txt` でエンジン（`priorwork` コマンド）の版を固定しているので、勝手に変わることはない。拡張機能を更新すると、ワークスペースの版が古いときに **エンジンを更新** を勧める。更新すると `AGENTS.md` とスキルも新しい版のものになる。`AGENTS.md` とスキルだけが古いときは、サイドバーに更新の行が出る。

## 11. 困ったとき

**エージェントがコマンドやスキル名を打つように求めてくる。** サイドバーに「スキルが古い」と出ていないか確かめ、出ていればその行で AGENTS.md とスキルを新しくする。それでも求められるときは、「Priorwork でサーベイを進めて」のように Priorwork の名前を添えて頼む。

**エージェントが `.venv` の中のファイル（`i18n.py` など）を開く。** Priorwork 本体のファイルで、サーベイには関係しない。閉じて構わない。直してはいけない（更新で上書きされる）。新しい AGENTS.md では開かないよう指示している。

**検索した件数が少ない。** 深さが full か確かめ（サーベイの右クリックの **調査範囲を編集**）、エージェントに「もっと検索して」と頼む。サイドバーの次にやることの **検索を足す** でも依頼文をコピーできる。

**HTML のレポートが Live Preview などで開けない。** SSH でつないだサーバーでは、ブラウザ用の拡張機能がサーバーの上のファイルを開けないことがある。[3.4](#34-レポートを見る)の方法で、Priorwork の中で開く。

**検索が「rate limited (HTTP 429)」で止まる。** Semantic Scholar の API キーが無いと、共有の枠を使うので混み合う。設定でキーを入れる。キーがあっても止まるときは、少し時間をおいてもう一度。待ち時間を延ばしながら最大5回まで自動で再試行する。

**論文が登録できない。** 国内学会誌（J-STAGE など）の論文は、Semantic Scholar にも OpenAlex にも無いことが多く、登録できない。国際査読誌を対象にする方針のため、いまは対象外だ。

**Python の環境が作れない。** 出力パネル（サイドバーのメニューの **出力を表示**）に原因が出ている。uv を入れられないときは、[python.org](https://www.python.org/) などから Python 3.10 以上を入れて、もう一度 **Python の環境（.venv）を用意する** を実行する。

**サイドバーに「priorwork コマンドが見つかりません」と出る。** ワークスペースの `.venv` がまだない。**Python の環境（.venv）を用意する** を実行する。

**何がおかしいか分からない。** **設定を診断（doctor）** で、設定・Git・接続をまとめて確かめる。
