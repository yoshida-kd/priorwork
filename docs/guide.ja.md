# Priorwork 手引き

> これは手引きの原稿。読むなら **<https://yoshida-kd.github.io/priorwork/ja/guide/>** で。 <!-- pages:skip -->

**社会科学の先行研究サーベイを、AI エージェントに任せて作る — ターミナルは不要**

Priorwork（prior work ＝ 先行研究）は、経済学・社会学・政治学・行政学・経営学・心理学などのテーマ別の先行研究サーベイを、AI エージェント（Claude Code・Antigravity など）に任せて作るための道具です。テーマを伝えれば、エージェントが範囲を決め、文献を探して選び、論文カードを書き、サーベイの文章を書き、検査して読める形に書き出します。あなたは結果を読み、VS Code のサイドバーで確かめて直します。

この手引きは使い方の全体です。短い紹介は [README](https://github.com/yoshida-kd/priorwork/blob/main/README.ja.md) にあります。
[English guide](https://yoshida-kd.github.io/priorwork/guide/)

---

## 1. はじめに

### 1.1 できること

- **任せる。** 「〇〇について先行研究をまとめて」と頼むだけで、エージェントが範囲の設定から書き出しまで止まらずに進めます。コマンドもスキル名も覚える必要はありません。
- **文献を探す。** Semantic Scholar で英語のキーワード検索（関連度順・ブール演算の bulk 検索）をし、DOI・掲載誌・ISSN を OpenAlex で照合します。採用した論文の参考文献と被引用をたどって、キーワード検索で漏れた論文も拾います。
- **論文カードを作る。** 採用した論文ごとに、RQ・説明変数・被説明変数・データ・識別戦略・結果・限界を記入したカードを作ります。カードから比較マトリクスが自動で作られます。
- **でっち上げを検出する。** 文章中の「著者 (年)」が登録済みの論文に対応しているか、DOI が別の論文を指していないかを機械的に検査します。
- **読める形に書き出す。** 管理用の印や未記入の欄を除いた HTML（Word・Markdown も可）を作り、VS Code の中で見られます（SSH でつないだサーバーでも）。
- **確かめて直す。** 採否とその理由、カード、検索の記録はすべて残ります。サイドバーの論文ごとのページで、採否を覆し、カードを直せます。

### 1.2 任せて、確かめる

エージェントは、範囲と採否を自分で決めて進めます。ただし、決めたことには必ず理由を残し、範囲もレポートに書き込みます。カードには要旨・本文に書かれていることだけを書き、何で確かめたか（確認レベル）を残します。あなたはそれを読んで、違うと思ったところを直します。直した採否やカードは、エージェントが次の作業で従います。

自分で一つずつ決めたいときは、エージェントに「相談しながら進めて」と伝えます（[4.6](#46-続きを頼む相談しながら進める)）。検索や選別を自分でサイドバーから行うこともできます（[5](#5-自分で操作する)）。

拡張機能が自分で AI のサービスを呼ぶことはありません。AI の手助けは、あなたがふだん使っているエージェントを通してだけ入ります。

### 1.3 必要なもの

| もの | 要るか | 説明 |
| :--- | :--- | :--- |
| VS Code と Priorwork の拡張機能 | 必須 | Linux・macOS。Windows では WSL の中で使う（[2.2](#22-windows-と-ssh-でつなぐサーバー)） |
| AI エージェント | 必須 | Claude Code・Antigravity など、VS Code で動き `AGENTS.md` を読むもの |
| Python 3.10 以上 | 自動 | 無ければ拡張機能が uv を入れ、uv が Python を取ってくる |
| git と GitHub のアカウント | 推奨 | ワークスペースを GitHub の非公開リポジトリに置く |
| Semantic Scholar の API キー | 推奨 | 無料。無いと検索がレート制限で失敗しやすい |
| Zotero | 任意 | 採用論文を Zotero に集める、Zotero の PDF から本文を読む |
| SSCI 収録誌のリスト | 任意 | Clarivate の Master Journal List の CSV。無ければ主要誌から推定 |

## 2. インストール

### 2.1 VS Code で

1. [VS Code](https://code.visualstudio.com/) を入れます。
2. 拡張機能のビューで **Priorwork** を探して入れます（[Marketplace](https://marketplace.visualstudio.com/items?itemName=yoshida-kd.priorwork)）。
3. アクティビティバーに Priorwork のアイコンが出ます。次の「[ワークスペースを作る](#3-ワークスペースを作る)」に進んでください。

Python は、ワークスペースを作るときに拡張機能が用意します。Python 3.10 以上が見つかればそれを使います。見つからなければ「uv を入れる」かを聞いてきます。uv（Astral の小さなツール）はホームフォルダーに入り、管理者権限は要りません。uv がワークスペース用の Python を取ってきます。

### 2.2 Windows と SSH でつなぐサーバー

- **Windows**: WSL（Ubuntu）を入れ、VS Code の **WSL** 拡張機能で WSL の中のフォルダを開いてから、上の手順を行います。Windows で直接使うことは確かめていません。
- **サーバー**: VS Code の **Remote - SSH** 拡張機能でサーバーにつなぎ、サーバーの上で上の手順を行います。拡張機能・Python・ワークスペースはサーバー側に入ります。書き出したレポートは Priorwork の中で見られます（[4.4](#44-レポートを見る)）。

### 2.3 コマンドラインで

拡張機能を使わない場合は、`priorwork` コマンドを PyPI から入れます。

```bash
mkdir my-surveys && cd my-surveys
python3 -m venv .venv
.venv/bin/pip install priorwork
.venv/bin/priorwork init --lang ja
./priorwork settings          # 設定の一覧（キーの値は表示しない）
./priorwork doctor --online   # 設定と接続の診断
```

## 3. ワークスペースを作る

**ワークスペース**は、サーベイのレポートとその状態を置くフォルダです。1つのワークスペースに、いくつでもサーベイを置けます。GitHub の非公開リポジトリで管理します。

### 3.1 作る

1. 空のフォルダを開くか、何も開いていない状態で、サイドバーの **ワークスペースを作る** を押します。
2. 場所と、レポートの言語（日本語・英語）を選びます。言語は後から変えられません。レポートの見出しと、エージェント向けの指示（`AGENTS.md` とスキル）がこの言語になります。
3. 拡張機能が `.venv` を作り、PyPI から `priorwork` を入れて、ワークスペースを用意します（`git init` も行います）。

### 3.2 設定する

サイドバーの歯車（**設定**）を開きます。

1. **Semantic Scholar** に API キーを入れます。[ここから無料で申し込めます](https://www.semanticscholar.org/product/api#api-key-form)。
2. Zotero を使うなら、**Zotero** の欄を埋めます（[8.2](#82-zotero)）。
3. SSCI 収録誌のリストがあれば、**SSCI リスト（CSV）を取り込む…** で取り込みます（[8.3](#83-ssci-収録誌のリスト)）。
4. **保存して接続を確かめる** を押すと、診断の結果がページの下に出ます。

設定はワークスペースの `.env` に保存されます。`.env` は Git に載りません。キーの値は設定のページに表示されません。

### 3.3 GitHub に置く

レポートと状態ファイルには論文の要旨が入るので、ワークスペースは**非公開**のリポジトリに置きます。

1. サイドバーの **まだ GitHub にありません — 非公開リポジトリとして公開する** を押します。
2. VS Code に聞かれたら **Publish to GitHub private repository**（非公開）を選び、示されたファイルをすべて含めます（`.env` は `.gitignore` で除かれています）。

エージェントは一区切りごとに変更をコミットします。push は、あなたが了承したときだけ行います。

### 3.4 別のマシンで続ける

1. VS Code でリポジトリを clone して開きます。
2. サイドバーのメニュー（…）の **Python の環境（.venv）を用意する** を実行します。
3. **設定** でキーを入れ直します（`.env` は Git に載らないため）。SSCI リストも取り込み直します。

## 4. AI に任せる

### 4.1 頼む

ワークスペースのフォルダを開いたまま、エージェントのチャットで頼みます。どちらの方法でも同じです。

- **チャットで普通の言葉で頼む。** 例:「行政需要の変化に対して行政組織がどう人材を確保するか、make or buy の観点で先行研究を full でまとめて」。コマンドやスキル名を打つ必要はありません（`/priorwork` と打っても構いません）。
- **サイドバーから頼む。** **新しいサーベイ** → **エージェントに任せる** で、テーマ（自由な言葉で）と深さを選ぶと、依頼文がコピーされます。通知の **Claude Code を開く** などでチャットを開き、貼ります。

リサーチクエスチョン・期間・採否の基準が決まっていれば、依頼に添えます。無ければエージェントがテーマから決め、最後の報告で「こう決めた」と伝えます。

### 4.2 エージェントがすること

エージェントは、ワークスペースの `AGENTS.md` とスキルに従い、次の順に止まらずに進めます。

```
① 範囲を決める → ② 検索 → ③ 選別 → ④ 引用をたどる → ⑤ カードを記入 → ⑥ 文章 → ⑦ 検査と書き出し
```

1. **範囲**: リサーチクエスチョン・期間・分野・採用基準・除外基準・深さを決め、サーベイを作ります。
2. **検索**: テーマをサブテーマに分け、英語のクエリで検索します。0 件のクエリは言い換えます。
3. **選別**: 候補を採用基準・除外基準に照らして、採用・保留・除外に分けます。どれにも理由を残します。
4. **引用をたどる**: 採用論文の参考文献と被引用から、キーワード検索で漏れた論文を拾って選別します。
5. **カード**: 採用論文の本文（Zotero の PDF かオープンアクセス版）か要旨から、カードを記入します。
6. **文章**: カードをもとに、背景・理論の潮流・実証手法の変遷・合意と論争・まとめを書きます。
7. **検査と書き出し**: 引用・DOI・未記入の欄を検査して直し、読むための版（HTML）を書き出します。

終わると、検索と採用の件数、自分で決めた範囲、残った注意点、レポートの見方を報告します。長い作業になるので、途中で「いまどこまで進んだか」を一行ずつ伝えることがあります（答えは待ちません）。

### 4.3 深さ

**深さ**はサーベイの規模の目安です。依頼に「quick」「さっと」「full」「網羅的に」などとあればそれに、無ければテーマの広さからエージェントが決めます。

| | quick（簡易） | full（本格） |
| :--- | :--- | :--- |
| 向くテーマ | 狭い・概観だけ欲しい | 広い・サブテーマがある・網羅性が要る |
| 検索 | 2〜3 クエリ（1 回 10 件） | サブテーマごとに 2〜4 クエリ（1 回 25 件）、候補 100 本以上が目安 |
| 引用をたどる | 任意 | 行う |
| カード | 要旨のみでよい | 中核の論文は本文で確かめる |
| 文章 | 概観と比較表 | 背景・学説・論争点・研究の空白まで |

full なのに検索が足りないと、サイドバーの **次にやること** に **検索を足す** が出ます。エージェントもこれを見て検索を足します。

### 4.4 レポートを見る

読むための版（HTML）は、VS Code の中で開きます。SSH でつないだサーバーでも、そのまま見られます。

- サイドバーでサーベイを右クリック → **レポートを書き出して見る**。
- エクスプローラーで `reports/<名前>.html` を右クリック → **Priorwork でレポートを見る**。
- エージェントが書き出したときは、通知の **見る** でも開けます。

未記入・未確認のカードや検査の ERROR が残っていると、冒頭に「下書き」と出ます。ブラウザで開いて PDF に印刷することもできます（ローカルのマシンのとき）。

### 4.5 確かめて直す

サイドバーのサーベイの下に、採用・保留・除外・未選別の論文が並びます。論文を押すと、論文ごとのページが開きます。

- **採否を確かめる**: 要旨と、エージェントが残した理由を見ます。違うと思えば **I** 採用、**M** 保留、**X** 除外（理由つき）で覆します。複数の論文は、サイドバーで選んで右クリックからまとめて変えられます。
- **カードを確かめる**: 採用論文のページで、カードを要旨と見比べ、直して **Ctrl+S** で保存します。
- **範囲を直す**: サーベイの右クリックの **調査範囲を編集** で、リサーチクエスチョン・基準・深さを変えます。

エージェントは、あなたが下した採否と直したカードを覆しません。直したあとで「続けて」と頼めば、それに合わせて進めます。

### 4.6 続きを頼む・相談しながら進める

- **続き**: チャットで「続きをやって」「もっと検索して」「カードを埋めて」などと頼みます。サーベイの右クリックの **エージェントに頼む…** でも、よく頼む作業（最後まで進める・検索を足す・選別・引用をたどる・カードの記入・文章・検査と修正）の依頼文をコピーできます。
- **相談しながら**: 「相談しながら進めて」「候補を 1 件ずつ見せて」と頼むと、エージェントは範囲と採否を推薦するだけにして、あなたの答えを待ちます。いつもそうしたいなら、ワークスペースの `AGENTS.local.md` に「範囲と採否はユーザーに相談してから決める」と書いておきます。

会話を再開したときも「続きをやろう」と言えば、エージェントが状態を確かめて次の作業に進みます。

### 4.7 Zotero に集める

Priorwork は Zotero に書き込みません。論文を Zotero に入れるのはあなたです。その手間を減らす方法が2つあります（Zotero 連携の設定は [8.2](#82-zotero)）。

**採用論文の DOI をまとめて Zotero に入れる。**

1. Zotero で、論文を入れたいコレクション（フォルダ）を選んでおきます。
2. サイドバーの次にやることの **Zotero に追加** を押し、**DOI をコピー** します（エージェントに「Zotero に入れたいので DOI の一覧をちょうだい」と頼んでも構いません）。
3. Zotero の **識別子でアイテムを追加**（魔法の杖）に貼って Enter を押します。選んでいたコレクションに入ります。
4. **Zotero から読み直す** を押すと、登録状況が更新されます。

**Zotero のコレクションをサーベイに結び付ける。** サーベイの右クリックの **Zotero のコレクションを結び付ける…** で、Zotero で作ったコレクションを選びます（エージェントに「Zotero の『〇〇』コレクションを使って」と伝えても構いません）。結び付けると:

- 「Zotero にあるか」は、そのコレクションに入っているかで判定します。
- コレクションに自分で入れた論文を、サーベイの候補に取り込めます（次にやることの **Zotero のコレクションの … 本を候補に登録する**）。エージェントは、範囲から明らかに外れない限り採用します。
- 本文は、そのコレクションの PDF を優先して読みます。

## 5. 自分で操作する

エージェントに任せずに、サイドバーから自分で進めることもできます。サイドバーのサーベイの下にある **次にやること** が、いま何をすればよいかを示します。項目を押すと、その操作が始まります。

### 5.1 範囲を決める

**新しいサーベイ** → **自分で作る** で、テーマ・英語のスラッグ（ファイル名になる。例: `minimum_wage_employment`）・深さ・リサーチクエスチョンを入れます。期間・分野・採用基準・除外基準は、サーベイの右クリックの **調査範囲を編集** で後から足せます。採用基準・除外基準は、論文のページの上に表示されます。

### 5.2 検索

**検索** に英語のクエリを入れ、検索の仕方を選びます。

- **検索**: Semantic Scholar の関連度検索（20件）。
- **Bulk 検索**: `+`（AND）、`|`（OR）、`-`（除外）、`"フレーズ"` が使え、被引用数の多い順（25件）。キーワード検索で埋もれる定番論文を拾えます。`AND`・`OR`・`NOT` と書いても、それぞれ `+`・`|`・`-` に直します。
- **SSCI 収録誌のみ**: 関連度検索のうち SSCI 収録誌のものだけ。

結果は候補として登録されます。同じ論文の WP 版と掲載版が両方あれば、掲載版だけを残します。書籍・WP・プレプリント・掲載誌不明のものは、既定で除かれます。DOI がすでに分かっている論文は **DOI を指定して追加** で登録できます。

### 5.3 選別

**候補を選別する** で、最初の未選別の論文のページが開きます。

- 上にサーベイの採用基準・除外基準、その下にタイトル・著者・掲載誌と SSCI の判定・被引用数・警告・要旨が出ます。
- **I** 採用、**M** 保留、**X** 除外（先に理由を入れる）、**U** 候補に戻す。決めると次の未選別の論文に進みます（設定 `priorwork.autoAdvance`）。
- **N** 次の未選別、**J / K** 次 / 前、**O** DOI をブラウザで開く。
- よく使った除外の理由は、ボタンで選べます。

警告（⚠️）の付いた論文は、採用する前に確かめます。

| 警告 | 意味 |
| :--- | :--- |
| DOI が別タイトルを指している | Semantic Scholar の DOI が別の論文（リプライなど）のもの |
| DOI は WP / プレプリント版 | 掲載誌は示されているが、DOI は SSRN などの版 |
| OpenAlex に DOI が見つからない / DOI なし / DOI 未照合 | DOI の誤り、欠落、または照合できなかった |
| 書評・コメントの可能性 | 「…, by 著者名」の形のタイトル、または 1 ページだけ |

### 5.4 引用をたどる

**引用をたどる（スナウボール）** は、採用した論文の参考文献と被引用論文を OpenAlex から集め、採用論文の何本と引用関係にあるかの多い順に候補として登録します。採用論文が 3 本以上なら、既定では 2 本以上とつながるものだけを候補にします。登録された候補は、5.3 と同じように選別します。

### 5.5 論文カードを記入する

採用した論文には、レポートの3章にカードが作られます。論文のページでカードを書き、**Ctrl+S** で保存します。本文は **本文を取得** で取り込めます（[6.3](#63-本文の取得)）。記入だけをエージェントに頼むなら、**エージェントに頼む… → 論文カードを記入する** です。カードについては[6](#6-論文カード)で詳しく説明します。

### 5.6 文章を書く

レポートの1章（背景）と4〜7章（理論の潮流・実証手法の変遷・合意と論争・まとめ）は、カードをもとに書く文章です。サーベイの **作業用のレポート（Markdown）を開く** で開いて書きます。エージェントに頼むなら **エージェントに頼む… → レポートの文章を書く** です。

### 5.7 検査と書き出し

1. **サーベイを検査** を押すと、問題が VS Code の **問題** パネルに並びます（[7](#7-検査)）。
2. **レポートを書き出して見る** で、読むための版（HTML）が開きます（[4.4](#44-レポートを見る)）。

## 6. 論文カード

### 6.1 欄

```
### #1 Acemoğlu et al. (2001): The Colonial Origins of Comparative Development
- 書誌: American Economic Review 91(5) | ✅ SSCI収録 | 被引用数 8534 | DOI   ← 自動
- 確認レベル: 未確認 / 要旨のみ / 本文確認済
- RQ: 制度は国家間の所得格差に因果的な影響を与えているか
- X（説明変数・介入）: 現代の制度の質
- Y（被説明変数・成果）: 1995年の1人当たりGDP
- データ・サンプル: 旧植民地64カ国
- 識別戦略: 2SLS。入植者の死亡率を操作変数に使う
- 主な結果: 制度の質は所得を大きく高める
- 限界: 死亡率データの測定誤差
- メモ:
```

- 見出しと書誌の行は自動で作られます。手で書くのは確認レベルからメモまでです。
- 各欄の**1行目**は比較マトリクス（2章）に載るので短く書きます。詳しいことは2行目以降に書くと、直下の箇条書きになります。
- 要旨・本文に書かれていることだけを書きます。書かれていなければ「記載なし」と書きます。

### 6.2 確認レベル

| 確認レベル | 意味 |
| :--- | :--- |
| 未確認 | まだ確かめていない（記入前、または推測が混じる） |
| 要旨のみ | 要旨で確かめた |
| 本文確認済 | 本文で確かめた |

未確認のカードは検査で警告され、書き出しは「下書き」になります。full のサーベイでは、中核の論文を本文で確かめます。

### 6.3 本文の取得

採用論文のページの **本文を取得** か、サイドバーの論文の右クリックで取得します（エージェントも同じ方法で取得します）。PDF はワークスペースに置かず、抽出したテキストだけを `.priorwork/cache/fulltext/`（Git 管理外）に残します。次の順に探します。

1. このマシンの Zotero の添付 PDF（DOI で照合）
2. Zotero Web API で見つけた添付 PDF（WebDAV、または Zotero のファイル同期）。サーベイに結び付けたコレクションのものを優先
3. Zotero が索引化した本文テキスト（ページ区切りが無い予備）
4. オープンアクセス版の PDF

出版社のサイトは自動のダウンロードを拒むことが多いので、オープンアクセスでない論文は Zotero に PDF を添付してから取得します。

### 6.4 採用を取り消したとき

採用を取り消した論文のカードは、記入内容ごと状態ファイルに退避され、もう一度採用すると戻ります。

## 7. 検査

**サーベイを検査** は次を調べます。

| 検査 | レベル |
| :--- | :--- |
| 文章・カード中の「著者 (年)」「(著者, 年; 著者, 年)」が登録済みの論文に対応しているか | ERROR（未登録）/ WARN（未採用） |
| 2001a / 2001b の区別が参照文献と合っているか | WARN |
| 文章中の DOI が登録済みか | ERROR |
| 採用論文の ⚠️、OpenAlex での DOI とタイトルの一致 | ERROR |
| カードの確認レベルと未記入の欄 | WARN |
| レポートが状態ファイルと一致しているか | WARN |
| 未選別の候補、SSCI 以外の採用論文、Zotero に無い採用論文、組織名・図表番号とみなした引用 | INFO |

引用の検出は正規表現によるもので、すべての書き方を拾うわけではありません。`Acemoglu et al. (2001, 2005)`、`Dell (2010, p. 5)`、`(e.g., Dell 2010; Acemoglu et al., 2001a)` は検出します。「World Bank (2010)」「OECD (2019)」のような組織名は INFO で伝えます。論文ではないのに引用と誤認されたものは、レポートに次のコメントを書くと外せます。

```markdown
<!-- priorwork:ignore-citation Smith (2015) -->
```

## 8. 設定

### 8.1 API キー

| 設定 | 用途 |
| :--- | :--- |
| Semantic Scholar の API キー | 推奨。無いと検索がレート制限（HTTP 429）で失敗しやすい |
| OpenAlex の API キー・メールアドレス | 任意。OpenAlex はキーが無くても使えるが、1日の利用量に上限がある |

### 8.2 Zotero

設定すると、採用論文が Zotero にあるかの確認、コレクションとの結び付け（[4.7](#47-zotero-に集める)）、Zotero に添付した PDF からの本文の取得ができます。Zotero にも WebDAV にも書き込みはしません。

1. <https://www.zotero.org/settings/keys> で API キーを作ります。権限は **Allow library access だけ**にします（notes・write は外す）。同じページの「Your user ID for use in API calls」がユーザー ID です。
2. 設定の **Zotero** にキーとユーザー ID を入れます。このマシンで Zotero を使っているなら、データフォルダ（既定 `~/Zotero`）も入れます。
3. ファイル同期に WebDAV（Nextcloud など）を使っているなら、**Zotero のファイル同期（WebDAV）** に、PDF の zip が置かれたフォルダの URL（Zotero に設定した URL ＋ `zotero/`）・ユーザー名・パスワードを入れます。Nextcloud なら、`zotero` フォルダを閲覧のみで専用のユーザーに共有し、そのユーザーのアプリパスワードを使うと安全です。
4. **保存して接続を確かめる** で確かめます。

WebDAV が「フォルダが見つかりません」になるときは URL を見直します。Nextcloud をサブパスに置いているなら、そのパスも含めます（例: `https://example.com/nextcloud/remote.php/dav/files/<ユーザー名>/zotero/`）。

### 8.3 SSCI 収録誌のリスト

SSCI に収録されているかは、Clarivate の [Master Journal List](https://mjl.clarivate.com/) でしか確定できません。そこで SSCI のリストを CSV でダウンロードし（無料のアカウントが要ります）、設定の **SSCI リスト（CSV）を取り込む…** で取り込みます。リストはワークスペースの `.priorwork/data/` にコピーされ、ライセンスの都合で Git には載りません。リストが無ければ、主要誌約100誌の内蔵リストから推定します。

| 表示 | 意味 |
| :--- | :--- |
| ✅ SSCI収録（リスト照合済） | リストと ISSN または誌名が一致 |
| 🟡 SSCI収録の可能性大（誌名推定・要確認） | リストが無く、内蔵リストと一致 |
| 🔍 学術誌（SSCI未確認） / ⚪ SSCI非収録誌 | SSCI か分からない / リストに無い |
| 📕 書籍 / ❌ WP・プレプリント / ❓ 掲載誌不明 | 既定で検索結果から除く |

### 8.4 VS Code の設定

| 設定 | 既定 | 説明 |
| :--- | :--- | :--- |
| `priorwork.command` | （空） | `priorwork` コマンド。空なら、ワークスペースの `.venv`、次に `PATH` の `priorwork` |
| `priorwork.python` | （空） | `.venv` を作るときの Python。空なら 3.10 以上を探し、無ければ uv を使う |
| `priorwork.autoAdvance` | `true` | 採否を決めたら次の未選別の論文に進む |

## 9. エージェントへの指示

### 9.1 AGENTS.md とスキル

ワークスペースには、エージェント向けの指示（`AGENTS.md`）と、工程ごとのスキル（`.agent/skills/`。`.claude/skills/` からも見える）が入っています。入口は `priorwork` スキルで、状態を見て次の工程のスキル（`priorwork-new`・`priorwork-screen`・`priorwork-snowball`・`priorwork-extract`・`priorwork-check`）に進みます。エージェントは依頼の言葉からこれらを選ぶので、名前を覚える必要はありません。

このワークスペースだけの指示（優先する分野・文体・除外したい誌名・「採否は相談して決める」など）は `AGENTS.local.md` に書きます。`AGENTS.md` とスキルはエンジンの版に合わせて書き換えられるので、直接編集しません。

### 9.2 エージェントが守ること

- 採否と範囲には理由を残し、あなたが下した判断を覆さない。
- 文章で触れる論文はすべて登録済みのもの。記憶だけで著者・年・DOI を書かない。
- カードには要旨・本文に書かれていることだけを書き、確認レベルを更新する。
- ⚠️ の付いた論文は掲載版に置き換えるか、保留にして伝える。🟡（誌名推定）を「SSCI 収録」と断定しない。
- 完成と言う前に検査を通す。
- Priorwork 本体（`.venv` の中）のファイルを開かない。
- Zotero に書き込まない。push はあなたの了承を得てから。

## 10. ワークスペースの中身

```text
my-surveys/
├── reports/                 # レポート（作業用の .md と、書き出した .html など）
├── AGENTS.md, CLAUDE.md     # エージェント向けの指示（自動で更新。直接編集しない）
├── AGENTS.local.md          # このワークスペースだけの指示（自由に編集）
├── .agent/skills/           # 工程ごとのスキル（.claude/skills からも見える）
├── priorwork                # ./priorwork（エージェントが使う）
├── requirements.txt         # エンジンの版（priorwork==X.Y.Z）
├── .env                     # 設定（Git に載らない）
└── .priorwork/
    ├── config.json          # ワークスペースの言語
    ├── surveys/             # サーベイの状態（Git に載る）
    ├── cache/               # 本文テキスト・Zotero の一覧（Git に載らない）
    └── data/                # SSCI リスト（Git に載らない）
```

| ファイル | 中身 | 編集 |
| :--- | :--- | :--- |
| `reports/YYYYMMDD_<slug>.md` | 作業用のレポート | 文章とカードの記入欄はエージェント（または手）で書く。`<!-- BEGIN priorwork:… -->` 〜 `<!-- END priorwork:… -->` は自動で作り直される |
| `.priorwork/surveys/YYYYMMDD_<slug>.json` | 候補・採否と理由（履歴つき）・検索の記録・範囲・深さ・Zotero のコレクション | Priorwork だけが書き換える |

レポートの8章（参照文献）は採用論文から DOI つきで作られ、付録には検索・件数・除外の理由・見直した採否の記録が残ります。

## 11. エンジンを更新する

ワークスペースは `requirements.txt` でエンジン（`priorwork` コマンド）の版を固定しているので、勝手に変わることはありません。拡張機能を更新すると、ワークスペースの版が古いときに **エンジンを更新** を勧めます。更新すると `AGENTS.md` とスキルも新しい版のものになります。`AGENTS.md` とスキルだけが古いときは、サイドバーに更新の行が出ます。

## 12. コマンドラインで使う

拡張機能と同じことは、すべて `./priorwork` コマンドでできます（エージェントもこれを使います）。

```bash
# ワークスペース
./priorwork init [DIR] [--lang ja|en]            # ワークスペースを作る
./priorwork settings [--stdin] [--import-ssci CSV]  # API キー・Zotero・SSCI リスト
./priorwork doctor [--online]                    # 設定と接続の診断
./priorwork sync [--force|--diff]                # AGENTS.md・スキルをエンジンの版に
./priorwork upgrade [--to X.Y.Z]                 # エンジンを更新

# サーベイ
./priorwork status [SURVEY]                      # 一覧 / 進捗と次にやること
./priorwork new "<テーマ>" --slug <slug> [--depth quick|full] [--question ...]
./priorwork scope SURVEY --question "..." [--years ... --fields ... --inclusion ... --exclusion ... --depth ...]
./priorwork list SURVEY [--status candidate maybe] [--abstract]
./priorwork include SURVEY 2 5 7 [--reason "..."]
./priorwork exclude SURVEY 3 --reason "理論モデルのみ"
./priorwork maybe SURVEY 9 / ./priorwork reset SURVEY 9
./priorwork add SURVEY <DOI>... [--candidate]
./priorwork card SURVEY 3 [--set rq="..." evidence=abstract]
./priorwork render SURVEY
./priorwork check SURVEY [--offline]
./priorwork export SURVEY [--format html|docx|md] [--with-abstracts]
./priorwork fulltext SURVEY <番号> [--pdf <パス>]

# Zotero（読むだけ）
./priorwork zotero [SURVEY] [--refresh]          # 連携の確認 / 採用論文の登録状況
./priorwork zotero --collections                 # コレクションの一覧
./priorwork zotero SURVEY --collection "<名前>"   # コレクションを結び付ける（"" で外す）
./priorwork zotero SURVEY --import               # コレクションの論文を候補に登録
./priorwork zotero SURVEY --dois                 # Zotero に無い採用論文の DOI（魔法の杖に貼る）

# 文献の探索
./priorwork search "<English query>" [--into SURVEY] [--bulk] [--sort citations|relevance|recent|cpy] [--year 2010-2024] [--ssci-only] [--limit N]
./priorwork snowball SURVEY [--direction both|references|citations] [--min-links N]
./priorwork get <DOI>
./priorwork citations <DOI> / ./priorwork references <DOI>
./priorwork journal "<誌名 or ISSN>"
```

`SURVEY` はファイル名（拡張子なし）か slug です。`--limit` の既定は、full のサーベイに登録するとき 25、それ以外は 10 です。多くのコマンドは `--json` で JSON を出力します。

## 13. 困ったとき

**エージェントがコマンドやスキル名を打つように求めてくる。** `./priorwork status` で「スキルが古い」と出ていないか確かめ、出ていればサイドバーの更新の行（または `./priorwork sync`）で AGENTS.md とスキルを新しくします。それでも求められるときは、「Priorwork でサーベイを進めて」のように Priorwork の名前を添えて頼みます。

**エージェントが `.venv` の中のファイル（`i18n.py` など）を開く。** Priorwork 本体のファイルで、サーベイには関係しません。閉じて構いません。直してはいけません（更新で上書きされます）。新しい AGENTS.md では開かないよう指示しています。

**検索した件数が少ない。** 深さが full か確かめ（サーベイの右クリックの **調査範囲を編集**）、エージェントに「もっと検索して」と頼みます。サイドバーの次にやることの **検索を足す** でも依頼文をコピーできます。

**HTML のレポートが Live Preview などで開けない。** SSH でつないだサーバーでは、ブラウザ用の拡張機能がサーバーの上のファイルを開けないことがあります。[4.4](#44-レポートを見る)の方法で、Priorwork の中で開きます。

**検索が「rate limited (HTTP 429)」で止まる。** Semantic Scholar の API キーが無いと、共有の枠を使うので混み合います。設定でキーを入れてください。キーがあっても止まるときは、少し時間をおいてもう一度。待ち時間を延ばしながら最大5回まで自動で再試行します。

**論文が登録できない。** 国内学会誌（J-STAGE など）の論文は、Semantic Scholar にも OpenAlex にも無いことが多く、登録できません。国際査読誌を対象にする方針のため、いまは対象外です。

**Python の環境が作れない。** 出力パネル（サイドバーのメニューの **出力を表示**）に原因が出ています。uv を入れられないときは、[python.org](https://www.python.org/) などから Python 3.10 以上を入れて、もう一度 **Python の環境（.venv）を用意する** を実行してください。

**サイドバーに「priorwork コマンドが見つかりません」と出る。** ワークスペースの `.venv` がまだありません。**Python の環境（.venv）を用意する** を実行します。

**何がおかしいか分からない。** **設定を診断（doctor）** で、設定・Git・接続をまとめて確かめます。
