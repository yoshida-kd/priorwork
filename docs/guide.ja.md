# Prior Work 手引き

> これは手引きの原稿。読むなら **<https://yoshida-kd.github.io/priorwork/ja/guide/>** で。 <!-- pages:skip -->

**AI エージェントと作る、社会科学の先行研究サーベイ — ターミナルは不要**

Prior Work は、経済学・社会学・政治学・経営学・心理学などのテーマ別の先行研究サーベイを、AI エージェント（Claude Code など）と作るための道具です。VS Code の拡張機能を入れれば、自分で行う操作（検索・選別・論文カードの確認・設定・検査・書き出し）はすべてサイドバーで、エージェントに頼む作業（本文からのカードの記入・サーベイの文章）はエージェントのチャットで行えます。

この手引きは使い方の全体です。短い紹介は [README](https://github.com/yoshida-kd/priorwork/blob/main/README.ja.md) にあります。
[English guide](https://yoshida-kd.github.io/priorwork/guide/)

---

## 1. はじめに

### 1.1 できること

- **文献を探す。** Semantic Scholar で英語のキーワード検索（関連度順・ブール演算の bulk 検索・SSCI 収録誌のみ）をし、DOI・掲載誌・ISSN を OpenAlex で照合します。採用した論文の参考文献と被引用をたどって、キーワード検索で漏れた論文も拾います。
- **選別する。** 候補を論文ごとのページで、要旨と採否基準を見ながら、キー 1 つで採用・保留・除外（理由つき）に分けます。エージェントに推薦させることもできます。
- **論文カードを作る。** 採用した論文ごとに、RQ・説明変数・被説明変数・データ・識別戦略・結果・限界を記入したカードを作ります。エージェントが要旨や本文から記入し、あなたが確かめて直します。カードから比較マトリクスが自動で作られます。
- **でっち上げを検出する。** 文章中の「著者 (年)」が登録済みの論文に対応しているか、DOI が別の論文を指していないかを機械的に検査します。
- **読める形に書き出す。** 管理用の印や未記入の欄を除いた HTML（Word・Markdown も可）を作ります。

### 1.2 決めるのはあなた

Prior Work は、AI に任せきりにしないための道具です。範囲（リサーチクエスチョン・期間・採否の基準）と論文の採否はあなたが決め、エージェントは推薦するだけです。カードは要旨・本文に書かれていることだけを書き、何で確かめたか（確認レベル）を残します。拡張機能が自分で AI のサービスを呼ぶことはありません。AI の手助けは、あなたがふだん使っているエージェントを通してだけ入ります。

### 1.3 必要なもの

| もの | 要るか | 説明 |
| :--- | :--- | :--- |
| VS Code と Prior Work の拡張機能 | 必須 | Linux・macOS。Windows では WSL の中で使う（[2.2](#22-windows-と-ssh-でつなぐサーバー)） |
| Python 3.10 以上 | 自動 | 無ければ拡張機能が uv を入れ、uv が Python を取ってくる |
| AI エージェント | 推奨 | Claude Code など、VS Code で動き `AGENTS.md` を読むもの。カードの記入と文章に使う |
| git と GitHub のアカウント | 推奨 | ワークスペースを GitHub の非公開リポジトリに置く |
| Semantic Scholar の API キー | 推奨 | 無料。無いと検索がレート制限で失敗しやすい |
| Zotero | 任意 | 採用論文が Zotero にあるかの確認と、添付 PDF からの本文の取得 |
| SSCI 収録誌のリスト | 任意 | Clarivate の Master Journal List の CSV。無ければ主要誌から推定 |

## 2. インストール

### 2.1 VS Code で

1. [VS Code](https://code.visualstudio.com/) を入れます。
2. 拡張機能のビューで **Prior Work** を探して入れます（[Marketplace](https://marketplace.visualstudio.com/items?itemName=yoshida-kd.priorwork)）。
3. アクティビティバーに Prior Work のアイコンが出ます。次の「[ワークスペースを作る](#3-ワークスペースを作る)」に進んでください。

Python は、ワークスペースを作るときに拡張機能が用意します。Python 3.10 以上が見つかればそれを使います。見つからなければ「uv を入れる」かを聞いてきます。uv（Astral の小さなツール）はホームフォルダーに入り、管理者権限は要りません。uv がワークスペース用の Python を取ってきます。

### 2.2 Windows と SSH でつなぐサーバー

- **Windows**: WSL（Ubuntu）を入れ、VS Code の **WSL** 拡張機能で WSL の中のフォルダを開いてから、上の手順を行います。Windows で直接使うことは確かめていません。
- **サーバー**: VS Code の **Remote - SSH** 拡張機能でサーバーにつなぎ、サーバーの上で上の手順を行います。拡張機能・Python・ワークスペースはサーバー側に入ります。

### 2.3 コマンドラインで

拡張機能を使わない場合や、エージェントだけで進める場合は、`priorwork` コマンドを PyPI から入れます。

```bash
mkdir my-surveys && cd my-surveys
python3 -m venv .venv
.venv/bin/pip install priorwork
.venv/bin/priorwork init --lang ja
./priorwork settings          # 設定の一覧（キーの値は表示しない）
./priorwork doctor --online   # 設定と接続の診断
```

## 3. ワークスペースを作る

**ワークスペース**は、サーベイのレポートとその状態を置くフォルダです。1つのワークスペースに、いくつでもサーベイを置けます。GitHub の非公開リポジトリで管理します。

### 3.1 作る

1. 空のフォルダを開くか、何も開いていない状態で、サイドバーの **ワークスペースを作る** を押します。
2. 場所と、レポートの言語（日本語・英語）を選びます。言語は後から変えられません。レポートの見出しと、エージェント向けの指示（`AGENTS.md` とスキル）がこの言語になります。
3. 拡張機能が `.venv` を作り、PyPI から `priorwork` を入れて、ワークスペースを用意します（`git init` も行います）。

### 3.2 設定する

サイドバーの歯車（**設定**）を開きます。

1. **Semantic Scholar** に API キーを入れます。[ここから無料で申し込めます](https://www.semanticscholar.org/product/api#api-key-form)。
2. Zotero を使うなら、**Zotero** の欄を埋めます（[7.2](#72-zotero)）。
3. SSCI 収録誌のリストがあれば、**SSCI リスト（CSV）を取り込む…** で取り込みます（[7.3](#73-ssci-収録誌のリスト)）。
4. **保存して接続を確かめる** を押すと、診断の結果がページの下に出ます。

設定はワークスペースの `.env` に保存されます。`.env` は Git に載りません。キーの値は設定のページに表示されません。

### 3.3 GitHub に置く

レポートと状態ファイルには論文の要旨が入るので、ワークスペースは**非公開**のリポジトリに置きます。

1. サイドバーの **まだ GitHub にありません — 非公開リポジトリとして公開する** を押します。
2. VS Code に聞かれたら **Publish to GitHub private repository**（非公開）を選び、示されたファイルをすべて含めます（`.env` は `.gitignore` で除かれています）。

以後の変更は、VS Code の **ソース管理** ビューからコミットして push します。エージェントも各工程の終わりにコミットを提案します。

### 3.4 別のマシンで続ける

1. VS Code でリポジトリを clone して開きます。
2. サイドバーのメニュー（…）の **Python の環境（.venv）を用意する** を実行します。
3. **設定** でキーを入れ直します（`.env` は Git に載らないため）。SSCI リストも取り込み直します。

## 4. サーベイの流れ

```
① 範囲を決める → ② 検索 → ③ 選別 → ④ 引用をたどる → ⑤ カードを記入 → ⑥ 文章 → ⑦ 検査と書き出し
```

サイドバーのサーベイの下にある **次にやること** が、いま何をすればよいかを示します。項目を押すと、その操作が始まります。

### 4.1 範囲を決める

**新しいサーベイ** で、テーマ・英語のスラッグ（ファイル名になる。例: `minimum_wage_employment`）・深さ・リサーチクエスチョンを入れます。期間・分野・採用基準・除外基準は、サーベイの右クリックの **調査範囲を編集** で後から足せます。採用基準・除外基準は、論文のページの上に表示されます。

**深さ**は、サーベイの規模の目安です。

| | quick（簡易） | full（本格） |
| :--- | :--- | :--- |
| 向くテーマ | 狭い・概観だけ欲しい | 広い・サブテーマがある・網羅性が要る |
| 検索 | 1〜2 クエリ | サブテーマごとに複数のクエリ |
| 引用をたどる | 任意 | 行う |
| カード | 要旨のみでよい | 中核論文は本文で確かめる |

エージェントと範囲を相談したいときは、チャットで「最低賃金の雇用効果についてサーベイを始めたい」のように話しかけます（スキル `/survey-new`）。

### 4.2 検索

**検索** に英語のクエリを入れ、検索の仕方を選びます。

- **検索**: Semantic Scholar の関連度検索（20件）。
- **Bulk 検索**: `+`（AND）、`|`（OR）、`-`（除外）、`"フレーズ"` が使え、被引用数の多い順（25件）。キーワード検索で埋もれる定番論文を拾えます。
- **SSCI 収録誌のみ**: 関連度検索のうち SSCI 収録誌のものだけ。

結果は候補として登録されます。同じ論文の WP 版と掲載版が両方あれば、掲載版だけを残します。書籍・WP・プレプリント・掲載誌不明のものは、既定で除かれます。DOI がすでに分かっている論文は **DOI を指定して追加** で登録できます。

### 4.3 選別

**候補を選別する** で、最初の未選別の論文のページが開きます。

- 上にサーベイの採用基準・除外基準、その下にタイトル・著者・掲載誌と SSCI の判定・被引用数・警告・要旨が出ます。
- **I** 採用、**M** 保留、**X** 除外（先に理由を入れる）、**U** 候補に戻す。決めると次の未選別の論文に進みます（設定 `priorwork.autoAdvance`）。
- **N** 次の未選別、**J / K** 次 / 前、**O** DOI をブラウザで開く。
- よく使った除外の理由は、ボタンで選べます。

サイドバーの論文を右クリックして、複数の論文をまとめて採用・保留・除外することもできます。

警告（⚠️）の付いた論文は、採用する前に確かめます。

| 警告 | 意味 |
| :--- | :--- |
| DOI が別タイトルを指している | Semantic Scholar の DOI が別の論文（リプライなど）のもの |
| DOI は WP / プレプリント版 | 掲載誌は示されているが、DOI は SSRN などの版 |
| OpenAlex に DOI が見つからない / DOI なし / DOI 未照合 | DOI の誤り、欠落、または照合できなかった |
| 書評・コメントの可能性 | 「…, by 著者名」の形のタイトル、または 1 ページだけ |

エージェントに推薦させるなら、サーベイの **エージェントに頼む… → 候補の採否を推薦する** で依頼文をコピーし、チャットに貼ります。エージェントは理由つきで推薦し、あなたの答えを待ってから記録します。

### 4.4 引用をたどる

**引用をたどる（スナウボール）** は、採用した論文の参考文献と被引用論文を OpenAlex から集め、採用論文の何本と引用関係にあるかの多い順に候補として登録します。採用論文が 3 本以上なら、既定では 2 本以上とつながるものだけを候補にします。登録された候補は、4.3 と同じように選別します。

### 4.5 論文カードを記入する

採用した論文には、レポートの3章にカードが作られます。記入はエージェントに頼むのが早道です。

1. 次にやることの **カードを記入** か、サーベイの **エージェントに頼む… → 論文カードを記入する** を押します。未記入の論文の番号が入った依頼文がコピーされます。
2. エージェントのチャットに貼ります。エージェントは本文を取得し（[5.3](#53-本文の取得)）、書かれていることだけをカードに書き、確認レベルを更新します。
3. 論文のページで、要旨と見比べてカードを確かめ、必要なら直して **Ctrl+S** で保存します。

カードについては[5](#5-論文カード)で詳しく説明します。

### 4.6 文章を書く

レポートの1章（背景）と4〜7章（理論の潮流・実証手法の変遷・合意と論争・まとめ）は、カードをもとに書く文章です。**エージェントに頼む… → レポートの文章を書く** で依頼できます。エージェントはサーベイに登録された論文だけを引用し、最後に検査を実行します。自分で書くときは、サーベイの **作業用のレポート（Markdown）を開く** で開いて書きます。

### 4.7 検査と書き出し

1. **サーベイを検査** を押すと、問題が VS Code の **問題** パネルに並びます（[6](#6-検査)）。直すのをエージェントに頼むなら **エージェントに頼む… → 検査して直す**。
2. **レポートを書き出して見る** で、読むための版（HTML）が開きます。未記入・未確認のカードや検査の ERROR が残っていると、冒頭に「下書き」と出ます。ブラウザで開いて PDF に印刷することもできます。

### 4.8 Zotero に登録する

Zotero 連携を設定していると、次にやることに **Zotero に追加** が出ます（Zotero に無い採用論文があるとき）。押すと、その論文の DOI をまとめてコピーできます。Zotero の **識別子でアイテムを追加**（魔法の杖）に貼って Enter を押し、**Zotero から読み直す** を押します。Prior Work は Zotero に書き込みません。

## 5. 論文カード

### 5.1 欄

```
### #1 Acemoğlu et al. (2001): The Colonial Origins of Comparative Development
- 書誌: American Economic Review 91(5) | ✅ SSCI収録 | 被引用数 8534 | DOI   ← 自動
- 確認レベル: 未確認 / 要旨のみ / 本文確認済
- RQ: 制度は国家間の所得格差に因果的な影響を与えているか
- X（説明変数・介入）: 現代の制度の質
- Y（被説明変数・成果）: 1995年の1人当たりGDP
- データ・サンプル: 旧植民地64カ国
- 識別戦略: 2SLS。入植者の死亡率を操作変数に使う
- 主な結果: 制度の質は所得を大きく高める
- 限界: 死亡率データの測定誤差
- メモ:
```

- 見出しと書誌の行は自動で作られます。手で書くのは確認レベルからメモまでです。
- 各欄の**1行目**は比較マトリクス（2章）に載るので短く書きます。詳しいことは2行目以降に書くと、直下の箇条書きになります。
- 要旨・本文に書かれていることだけを書きます。書かれていなければ「記載なし」と書きます。

### 5.2 確認レベル

| 確認レベル | 意味 |
| :--- | :--- |
| 未確認 | まだ確かめていない（記入前、または推測が混じる） |
| 要旨のみ | 要旨で確かめた |
| 本文確認済 | 本文で確かめた |

未確認のカードは検査で警告され、書き出しは「下書き」になります。full のサーベイでは、中核の論文を本文で確かめることを勧めます。

### 5.3 本文の取得

採用論文のページの **本文を取得** か、サイドバーの論文の右クリックで取得します。PDF はワークスペースに置かず、抽出したテキストだけを `.priorwork/cache/fulltext/`（Git 管理外）に残します。次の順に探します。

1. このマシンの Zotero の添付 PDF（DOI で照合）
2. Zotero Web API で見つけた添付 PDF（WebDAV、または Zotero のファイル同期）
3. Zotero が索引化した本文テキスト（ページ区切りが無い予備）
4. オープンアクセス版の PDF

出版社のサイトは自動のダウンロードを拒むことが多いので、オープンアクセスでない論文は Zotero に PDF を添付してから取得します。

### 5.4 採用を取り消したとき

採用を取り消した論文のカードは、記入内容ごと状態ファイルに退避され、もう一度採用すると戻ります。

## 6. 検査

**サーベイを検査** は次を調べます。

| 検査 | レベル |
| :--- | :--- |
| 文章・カード中の「著者 (年)」「(著者, 年; 著者, 年)」が登録済みの論文に対応しているか | ERROR（未登録）/ WARN（未採用） |
| 2001a / 2001b の区別が参照文献と合っているか | WARN |
| 文章中の DOI が登録済みか | ERROR |
| 採用論文の ⚠️、OpenAlex での DOI とタイトルの一致 | ERROR |
| カードの確認レベルと未記入の欄 | WARN |
| レポートが状態ファイルと一致しているか | WARN |
| 未選別の候補、SSCI 以外の採用論文、Zotero に無い採用論文、組織名・図表番号とみなした引用 | INFO |

引用の検出は正規表現によるもので、すべての書き方を拾うわけではありません。`Acemoglu et al. (2001, 2005)`、`Dell (2010, p. 5)`、`(e.g., Dell 2010; Acemoglu et al., 2001a)` は検出します。「World Bank (2010)」「OECD (2019)」のような組織名は INFO で伝えます。論文ではないのに引用と誤認されたものは、レポートに次のコメントを書くと外せます。

```markdown
<!-- priorwork:ignore-citation Smith (2015) -->
```

## 7. 設定

### 7.1 API キー

| 設定 | 用途 |
| :--- | :--- |
| Semantic Scholar の API キー | 推奨。無いと検索がレート制限（HTTP 429）で失敗しやすい |
| OpenAlex の API キー・メールアドレス | 任意。OpenAlex はキーが無くても使えるが、1日の利用量に上限がある |

### 7.2 Zotero

設定すると、採用論文が Zotero にあるかの確認と、Zotero に添付した PDF からの本文の取得ができます。Zotero にも WebDAV にも書き込みはしません。

1. <https://www.zotero.org/settings/keys> で API キーを作ります。権限は **Allow library access だけ**にします（notes・write は外す）。同じページの「Your user ID for use in API calls」がユーザー ID です。
2. 設定の **Zotero** にキーとユーザー ID を入れます。このマシンで Zotero を使っているなら、データフォルダ（既定 `~/Zotero`）も入れます。
3. ファイル同期に WebDAV（Nextcloud など）を使っているなら、**Zotero のファイル同期（WebDAV）** に、PDF の zip が置かれたフォルダの URL（Zotero に設定した URL ＋ `zotero/`）・ユーザー名・パスワードを入れます。Nextcloud なら、`zotero` フォルダを閲覧のみで専用のユーザーに共有し、そのユーザーのアプリパスワードを使うと安全です。
4. **保存して接続を確かめる** で確かめます。

WebDAV が「フォルダが見つかりません」になるときは URL を見直します。Nextcloud をサブパスに置いているなら、そのパスも含めます（例: `https://example.com/nextcloud/remote.php/dav/files/<ユーザー名>/zotero/`）。

### 7.3 SSCI 収録誌のリスト

SSCI に収録されているかは、Clarivate の [Master Journal List](https://mjl.clarivate.com/) でしか確定できません。そこで SSCI のリストを CSV でダウンロードし（無料のアカウントが要ります）、設定の **SSCI リスト（CSV）を取り込む…** で取り込みます。リストはワークスペースの `.priorwork/data/` にコピーされ、ライセンスの都合で Git には載りません。リストが無ければ、主要誌約100誌の内蔵リストから推定します。

| 表示 | 意味 |
| :--- | :--- |
| ✅ SSCI収録（リスト照合済） | リストと ISSN または誌名が一致 |
| 🟡 SSCI収録の可能性大（誌名推定・要確認） | リストが無く、内蔵リストと一致 |
| 🔍 学術誌（SSCI未確認） / ⚪ SSCI非収録誌 | SSCI か分からない / リストに無い |
| 📕 書籍 / ❌ WP・プレプリント / ❓ 掲載誌不明 | 既定で検索結果から除く |

### 7.4 VS Code の設定

| 設定 | 既定 | 説明 |
| :--- | :--- | :--- |
| `priorwork.command` | （空） | `priorwork` コマンド。空なら、ワークスペースの `.venv`、次に `PATH` の `priorwork` |
| `priorwork.python` | （空） | `.venv` を作るときの Python。空なら 3.10 以上を探し、無ければ uv を使う |
| `priorwork.autoAdvance` | `true` | 採否を決めたら次の未選別の論文に進む |

## 8. エージェントと進める

### 8.1 頼み方

ワークスペースには、エージェント向けの指示（`AGENTS.md`）と工程ごとのスキルが入っています。Claude Code などでワークスペースを開いて話しかけると、エージェントはそれに従って進めます。

サーベイの **エージェントに頼む…** は、よく頼む作業の依頼文をコピーします。

| 頼むこと | スキル | あなたが決めること |
| :--- | :--- | :--- |
| 論文カードを記入する | `/survey-extract` | PDF の場所、要旨だけで進めるか |
| 候補の採否を推薦する | `/survey-screen` | 採用 / 除外（理由つき）/ 保留 |
| 引用をたどる | `/survey-snowball` | 新しい候補の採否 |
| レポートの文章を書く | — | 内容の確認 |
| 検査して直す | `/survey-check` | 解決できなかった指摘の扱い |

会話を再開したときは「続きをやろう」と言えば、エージェントが進捗と次の作業を確かめます。

### 8.2 エージェントが守ること

- 採否は推薦するだけで、あなたの答えを待つ。
- 文章で触れる論文はすべて登録済みのもの。記憶だけで著者・年・DOI を書かない。
- カードには要旨・本文に書かれていることだけを書き、確認レベルを更新する。
- ⚠️ の付いた論文はあなたに伝える。🟡（誌名推定）を「SSCI 収録」と断定しない。
- 完成と言う前に検査を通す。

このワークスペースだけの指示（優先する分野・文体・除外したい誌名など）は `AGENTS.local.md` に書きます。`AGENTS.md` とスキルはエンジンの版に合わせて書き換えられるので、直接編集しません。

## 9. ワークスペースの中身

```text
my-surveys/
├── reports/                 # レポート（作業用の .md と、書き出した .html など）
├── AGENTS.md, CLAUDE.md     # エージェント向けの指示（自動で更新。直接編集しない）
├── AGENTS.local.md          # このワークスペースだけの指示（自由に編集）
├── .agent/skills/           # 工程ごとのスキル（.claude/skills からも見える）
├── priorwork                # ./priorwork（エージェントが使う）
├── requirements.txt         # エンジンの版（priorwork==X.Y.Z）
├── .env                     # 設定（Git に載らない）
└── .priorwork/
    ├── config.json          # ワークスペースの言語
    ├── surveys/             # サーベイの状態（Git に載る）
    ├── cache/               # 本文テキスト・Zotero の一覧（Git に載らない）
    └── data/                # SSCI リスト（Git に載らない）
```

| ファイル | 中身 | 編集 |
| :--- | :--- | :--- |
| `reports/YYYYMMDD_<slug>.md` | 作業用のレポート | 文章とカードの記入欄は手で（またはエージェントが）書く。`<!-- BEGIN priorwork:… -->` 〜 `<!-- END priorwork:… -->` は自動で作り直される |
| `.priorwork/surveys/YYYYMMDD_<slug>.json` | 候補・採否と理由（履歴つき）・検索の記録・範囲・深さ | Prior Work だけが書き換える |

レポートの8章（参照文献）は採用論文から DOI つきで作られ、付録には検索・件数・除外の理由・見直した採否の記録が残ります。

## 10. エンジンを更新する

ワークスペースは `requirements.txt` でエンジン（`priorwork` コマンド）の版を固定しているので、勝手に変わることはありません。拡張機能を更新すると、ワークスペースの版が古いときに **エンジンを更新** を勧めます。更新すると `AGENTS.md` とスキルも新しい版のものになります。`AGENTS.md` とスキルだけが古いときは、サイドバーに更新の行が出ます。

## 11. コマンドラインで使う

拡張機能と同じことは、すべて `./priorwork` コマンドでできます（エージェントもこれを使います）。

```bash
# ワークスペース
./priorwork init [DIR] [--lang ja|en]            # ワークスペースを作る
./priorwork settings [--stdin] [--import-ssci CSV]  # API キー・Zotero・SSCI リスト
./priorwork doctor [--online]                    # 設定と接続の診断
./priorwork sync [--force|--diff]                # AGENTS.md・スキルをエンジンの版に
./priorwork upgrade [--to X.Y.Z]                 # エンジンを更新

# サーベイ
./priorwork status [SURVEY]                      # 一覧 / 進捗と次にやること
./priorwork new "<テーマ>" --slug <slug> [--depth quick|full] [--question ...]
./priorwork scope SURVEY --question "..." [--years ... --fields ... --inclusion ... --exclusion ... --depth ...]
./priorwork list SURVEY [--status candidate maybe] [--abstract]
./priorwork include SURVEY 2 5 7
./priorwork exclude SURVEY 3 --reason "理論モデルのみ"
./priorwork maybe SURVEY 9 / ./priorwork reset SURVEY 9
./priorwork add SURVEY <DOI>... [--candidate]
./priorwork card SURVEY 3 [--set rq="..." evidence=abstract]
./priorwork render SURVEY
./priorwork check SURVEY [--offline]
./priorwork export SURVEY [--format html|docx|md] [--with-abstracts]
./priorwork fulltext SURVEY <番号> [--pdf <パス>]
./priorwork zotero [SURVEY] [--refresh]

# 文献の探索
./priorwork search "<English query>" [--into SURVEY] [--bulk] [--sort citations|relevance|recent|cpy] [--year 2010-2024] [--ssci-only]
./priorwork snowball SURVEY [--direction both|references|citations] [--min-links N]
./priorwork get <DOI>
./priorwork citations <DOI> / ./priorwork references <DOI>
./priorwork journal "<誌名 or ISSN>"
```

`SURVEY` はファイル名（拡張子なし）か slug です。多くのコマンドは `--json` で JSON を出力します。

## 12. 困ったとき

**検索が「rate limited (HTTP 429)」で止まる。** Semantic Scholar の API キーが無いと、共有の枠を使うので混み合います。設定でキーを入れてください。キーがあっても止まるときは、少し時間をおいてもう一度。待ち時間を延ばしながら最大5回まで自動で再試行します。

**論文が登録できない。** 国内学会誌（J-STAGE など）の論文は、Semantic Scholar にも OpenAlex にも無いことが多く、登録できません。国際査読誌を対象にする方針のため、いまは対象外です。

**Python の環境が作れない。** 出力パネル（サイドバーのメニューの **出力を表示**）に原因が出ています。uv を入れられないときは、[python.org](https://www.python.org/) などから Python 3.10 以上を入れて、もう一度 **Python の環境（.venv）を用意する** を実行してください。

**サイドバーに「priorwork コマンドが見つかりません」と出る。** ワークスペースの `.venv` がまだありません。**Python の環境（.venv）を用意する** を実行します。

**何がおかしいか分からない。** **設定を診断（doctor）** で、設定・Git・接続をまとめて確かめます。

不具合の報告や要望は [Issues](https://github.com/yoshida-kd/priorwork/issues) へどうぞ。
