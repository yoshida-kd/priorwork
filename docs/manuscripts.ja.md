# 原稿から始める

> これはこのページの原稿。読むなら **<https://yoshida-kd.github.io/priorwork/ja/manuscripts/>** で。 <!-- pages:skip -->

テーマではなく、手元の原稿（書きかけでも構わない）から始めることもできる。**1 本の原稿に、サーベイとレポートは 1 本** で、エージェントは原稿に必要なところに力を入れる。

| 原稿 | レポートから主に得られるもの |
| :--- | :--- |
| 書きかけ | 節ごとの欠けと、どこに何を足すか |
| 分析まで済んで、イントロ・先行研究・理論がまだ | その部分を、原稿の言語で書いたもの |
| 出来上がっている | 引用の点検、足りない先行研究、論の組み立てへのコメント |

## 1. 原稿の置き場所

`manuscripts/` に、論文ごとのフォルダを作って入れる（`manuscripts/README.md` にも同じ説明がある）。

```text
manuscripts/
  make_or_buy/          ← 論文ごとのフォルダ（英数字の名前）
    paper.md            ← 原稿。書けているところだけでよい
    tables/             ← 結果の表・図・ログ（原稿に入っていないものがあれば）
```

形式は問わない。Markdown・Quarto（.qmd とその HTML）・LaTeX・Word（.docx）・PDF を読める。

## 2. 頼み方

サイドバーの **新しいサーベイ → 原稿から始める** で原稿（かフォルダ）を選ぶと、依頼文がコピーされる。ワークスペースの外の原稿を選ぶと、`manuscripts/` に写すかを聞く（元の場所のものはそのまま）。チャットで頼んでもよい。

> manuscripts/make_or_buy の原稿は書きかけ。足りないところを先行研究で補って

> manuscripts/make_or_buy の原稿は分析まで書いてある。イントロ・先行研究・理論と仮説を書いて

> manuscripts/make_or_buy の原稿に足りない先行研究と、引用の仕方のまずいところを指摘して

## 3. 手伝ってほしい所に印を残す

書きながら、引用が要る所に `[cite]`、論文を引きたい所に `[@?]`、何を補ってほしいかを `TODO(priorwork): <頼みたいこと>` と 1 行で残す。エージェントはそれを先に埋め、埋められなかったものとその理由を伝える。

## 4. 何を作るかを相談して決める

エージェントは原稿を読み、力を入れるところ、原稿のどこを対象にするか、検索の範囲を提案して、答えを待つ。依頼でこれらがはっきりしていれば、そのまま進める。

## 5. レポートの中身


| 節 | 中身 |
| :--- | :--- |
| まず直すところ | 大事な点を順に |
| 原稿の欠けの地図 | 節ごとの状態と、あなたの印 |
| 文献で支える主張 | 支える文献と、**食い違う文献** |
| 補完の一覧 | 原稿の順に 1 項目ずつ。**場所**（前後の一文の引用）・**理由**・本文。文献で支えられることだけで、方法や結果の中身は書かない |
| 引用の点検 | 箇所ごとに、合う / 向きが違う / 言い過ぎ / 根拠が弱い と、勧める直し |
| 足りない先行研究 | どこで、何のために引くか |
| 仮説と文献 | 仮説ごとの根拠の文献と、食い違う文献 |
| 論の組み立て | 問い・空白・仮説・方法・結果・貢献のつながり |

論文カードには **原稿での役割** が付き、比較マトリクスにも出る。頼まれていない節は「対象外」と書かれる。

原稿そのものは書き換えない。レポートを読んで、あなたが原稿を直す。足すものは、エージェントが参考文献つきで `reports/<名前>.draft.md` に書き出す。Octavo の原稿なら、プロジェクトの受け取り場所に届く（下の節）。

前の版で下書きや助言として作ったサーベイは、そのレポートのまま続けられる。

## 6. Octavo の原稿と合わせる

[Octavo](https://github.com/yoshida-kd/octavo)（Markdown と Quarto で論文を書く道具）で書いている原稿は、Octavo のプロジェクト（別のリポジトリ）に置いたまま使える。1 つの Priorwork のワークスペースで、いくつもの Octavo のプロジェクトの論文を扱える。

Octavo 側のコレクションを選ぶ画面、コレクションの並び、**Priorwork で先行研究を頼む** は、0.6.4 より後の Octavo で使える。

### つなぎ目は Zotero のコレクション

Octavo は、設定の `zotero_collection` に書いたコレクションから参考文献の `.bib` を取ってくる。Priorwork のサーベイも同じコレクションに結び付ければ、採用論文をそこに入れるだけで、Octavo の原稿の参考文献にもなる。

1. Octavo のプロジェクトで、論文のコレクションを決める（Octavo のサイドバーの **Zotero のコレクションを選ぶ**）。
2. Octavo のサイドバーで論文を右クリック →（または Priorwork の **新しいサーベイ → 原稿から始める** で、Octavo のプロジェクトの論文を選ぶ）**Priorwork で先行研究を頼む** で依頼文をコピーし、Priorwork のワークスペースのウィンドウで、エージェントのチャットに貼る。2 つは別のウィンドウなので、依頼文で受け渡す。
3. エージェントは、原稿のほかにプロジェクトの分析の結果・表と、原稿が引いている文献（`.bib`）を読み、原稿が引いている論文を登録する。サーベイは、Octavo と同じ Zotero のコレクションに結び付く。
4. 下書きは Octavo の形で、Octavo のプロジェクトの受け取り場所に書き出される（`literature/priorwork/<サーベイ>.md` と、添え状の `.json`、採用論文のカードの `<サーベイ>.cards.json`。Octavo は原稿の `[@key]` の上にカードの要点と確認レベルを出せる）。引用は `.bib` のキーで `[@key]` になり、参考文献の節は Octavo が作る。Priorwork は原稿を書き換えない。原稿への取り込みは、Octavo のプロジェクトのエージェントに「Priorwork から受け取った下書きを原稿に反映して」と頼む（自分で読んで移しても構わない）。
5. `.bib` にまだ無い論文は `[@PRIORWORK:<DOI>]` と書かれ、DOI の一覧が出る。Zotero のコレクションに入れ（[手引き 3.7](https://yoshida-kd.github.io/priorwork/ja/guide/#37-zotero-に集める)。Priorwork に入れさせることもできる）、Octavo で文献を取得し直してから、Octavo のサイドバーの **印を .bib のキーに置き換える** を押すと、DOI から `[@key]` に置き換わる（それまで Octavo の検査は「無いキー」として知らせる）。

### クリップボードを使わない依頼

Priorwork のワークスペースの場所を知っている Octavo は、依頼文をコピーする代わりに、ワークスペースの `.priorwork/requests/` に依頼を置く。依頼はサイドバーの一番上の **Octavo からの依頼** に出る。押すと、エージェントに頼む（依頼を指す短い依頼文をコピーする）か、理由を添えて断る（理由は Octavo から読める）かを選べる。エージェントは済んだらそれを記録し、Octavo にもそれが出る。

### 1 つのサーベイを、いくつもの論文で

テーマのサーベイ（例: 外部委託の先行研究）を、いくつもの論文で使うこともできる。サーベイを右クリック → **Octavo のプロジェクトに結び付ける…** でプロジェクトのフォルダを選び（いくつでも）、**Octavo のプロジェクト用に書き出す…** で、そのプロジェクトの `.bib` のキーを使った学説・手法・論争・空白の節が、そのプロジェクトの受け取り場所 `literature/priorwork/<サーベイ>.md` に出る。Octavo 側では、プロジェクトのコレクションにサーベイのコレクションを足す（Octavo の **Zotero のコレクションを選ぶ** では、いくつでも印を付けられる）。

### 1 つの Octavo のプロジェクトに、いくつものサーベイ

1 本の論文のために、理論・方法など切り口ごとにサーベイを分けることもある（別のワークスペースのサーベイでも構わない）。そのときは、Octavo のプロジェクトのコレクション（例: 「Make or buy」）の下に、サーベイごとのコレクション（「Make or buy / 理論」「Make or buy / 方法」）を Zotero で作り、それぞれのサーベイに結び付ける。Octavo の文献の取得は下のコレクションの文献も取るので、どのサーベイの採用論文も 1 つの `.bib` に入る。サイドバーのコレクションの一覧では、Octavo のコレクションとその下のものが先頭に出る。サーベイの状況には、同じ Octavo のプロジェクトのほかのサーベイも出る。

Priorwork は Octavo のプロジェクトのファイルを書き換えない。サーベイと Octavo のコレクションが違うと、検査が知らせる。原稿の場所はワークスペースからの相対パス（例: `../make_or_buy/papers/main`）で記録されるので、別のマシンでも、リポジトリを同じように並べて clone すればそのまま動く。
