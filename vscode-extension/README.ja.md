# Priorwork

**先行研究サーベイを AI エージェントに任せて、確かめる — ターミナルは不要。**

[English](README.md)

Priorwork は、テーマ別の先行研究サーベイを Git のワークスペースで管理します。AI エージェント
（Claude Code・Antigravity など `AGENTS.md` を読むエージェント）にテーマを普通の言葉で伝えると、
範囲を決め、Semantic Scholar・OpenAlex で探し、理由を残しながら選別し、引用をたどり、論文ごとの
カードを埋め、文章を書いて検査し、書き出すところまで止まらずに進めます。この拡張機能は、その仕事を
ターミナルなしで確かめて直す場所です。拡張機能が自分で AI のサービスを呼ぶことはありません。

- **エージェントに頼む。** 「新しいサーベイ → エージェントに任せる」がサーベイ全体の依頼文を、
  サーベイの「エージェントに頼む…」が続き・検索の追加・選別・引用の追跡・カードの記入・文章・検査の
  依頼文をコピーします。Claude Code・Antigravity・Copilot が入っていれば、ボタンでチャットを開けます。
  チャットで直接頼んでも構いません（スキル名は要りません）。
- **サイドバーにサーベイ。** サーベイごとに、未選別の件数、次にやること、論文（未選別・保留・
  採用・除外）を表示します。
- **論文ごとのページ。** タイトル・著者・掲載誌と SSCI の判定・被引用数・警告（DOI が別の論文を
  指している、WP 版の DOI、書評の可能性）・要旨を表示し、上にサーベイの採用基準・除外基準を
  出し、エージェントが残した理由も表示します。クリックかキーで覆せます（**I** 採用・**M** 保留・
  **X** 除外（理由つき））。採用論文のページには**論文カード**（RQ・X・Y・データ・識別戦略・結果・限界・確認レベル）
  も表示され、エージェントが書いた内容を確かめて直せます（**Ctrl+S** で保存）。
- **検索とスナウボール。** 英語で検索し（関連度順・ブール演算の bulk 検索・SSCI 収録誌のみ）、
  採用した論文の参考文献・被引用をたどって、キーワード検索で漏れた論文を拾います。
- **信頼できる検査。** 「サーベイを検査」は、本文中の「著者 (年)」のうち登録されていないもの、
  別のタイトルを指す DOI、未記入のカードを問題パネルに並べます。
- **レポートは VS Code の中で。** 「レポートを書き出して見る」か、`reports/*.html` を右クリック →
  「Priorwork でレポートを見る」で、読むための版を表示します（完成するまで「下書き」）。SSH で
  つないだサーバーでも見られます。エージェントが書き出すと、通知から開けます。
- **Zotero は読むだけ。** Zotero のコレクションをサーベイに結び付けると、そこに無い採用論文の DOI を
  まとめてコピーして魔法の杖に貼れ、自分で入れた論文を候補に取り込め、本文はそこの PDF から先に読みます。
- **ファイルを開かずに設定。** API キー・Zotero・SSCI リストを 1 つのページで設定し、接続も確かめられます
  （キーの値は表示しません）。サイドバーの行から、ワークスペースを GitHub の非公開リポジトリに公開できます。

## 始め方

1. 拡張機能を入れます。始めるのにほかに入れるものはありません。Python 3.10 以上があればそれを使い、
   無ければ [uv](https://docs.astral.sh/uv/) を入れて Python を取ってきます（ホームフォルダーに入り、
   管理者権限は要りません）。VS Code で動く AI エージェント（Claude Code・Antigravity など）と、
   ワークスペースを GitHub に置くための **git** を用意してください。
2. **Priorwork: ワークスペースを作る…**（Priorwork のサイドバーのボタンでも可）を実行し、
   空のフォルダとレポートの言語（日本語・英語）を選びます。拡張機能がそこに `.venv` を作り、
   PyPI から `priorwork` コマンドを入れます。
3. サイドバーの歯車の **設定** で、[Semantic Scholar の API キー](https://www.semanticscholar.org/product/api#api-key-form)
   （無料）を入れます（無いと検索がレート制限にかかりやすい）。Zotero と SSCI リストも任意でここで設定でき、
   **保存して接続を確かめる** で動くかを確かめられます。
4. **新しいサーベイ…** → **エージェントに任せる**: テーマと深さを入れ、コピーされた依頼文を
   エージェントのチャットに貼ります（チャットで直接頼んでも同じです）。
5. エージェントが書き出したらレポートを読み、論文ごとのページで採否とカードを確かめ、違うところを
   直します。エージェントはあなたの変更に従います。
6. 続きはサーベイの **エージェントに頼む…** で。検索と選別を自分で行うなら、4 で **自分で作る** を
   選び、**検索…** と **候補を選別する** を使います。

ワークスペースは GitHub の**非公開**リポジトリで管理してください（サイドバーの「まだ GitHub に
ありません」の行から設定できます）。レポートと状態ファイルには要旨が入るためです。API キーが入る
`.env` は Git に載りません。

## コマンド

| コマンド | すること |
| :--- | :--- |
| ワークスペースを作る… | フォルダにワークスペース（と `.venv`）を用意する |
| 新しいサーベイ… / 調査範囲を編集… | サーベイを作る。リサーチクエスチョン・期間・採否基準・深さを変える |
| 検索… / 引用をたどる（スナウボール） / DOI を指定して追加… | 候補を探す |
| 候補を選別する | 最初の未選別の論文のページを開く |
| 採用 / 保留 / 除外… / 候補に戻す | サイドバーからも。複数の論文をまとめて |
| 本文を取得 | Zotero かオープンアクセスの PDF から（採用論文） |
| サーベイを検査 | 指摘を問題パネルに |
| エージェントに頼む… | 続き・検索の追加・カードの記入などの依頼文をコピーし、エージェントのチャットに貼る |
| レポートを書き出して見る / Priorwork でレポートを見る | 読むための版（HTML）を VS Code の中で |
| Zotero のコレクションを結び付ける… | Zotero のコレクションをサーベイに結び付ける（Zotero には書き込まない） |
| 設定（API キー・Zotero・SSCI リスト）… | キーと Zotero を設定し、SSCI リストを取り込み、接続を確かめる |
| 設定を診断（doctor） | API キー・SSCI リスト・Git・接続 |
| ワークスペースを GitHub に公開（非公開）… | VS Code の「GitHub に公開」を、非公開にする念押しつきで |
| AGENTS.md・スキルを更新（sync） / エンジンを更新（upgrade） | ワークスペースをエンジンの版に合わせる |

## 設定

| 設定 | 既定 | |
| :--- | :--- | :--- |
| `priorwork.command` | （空） | `priorwork` コマンド。空なら、ワークスペースの `.venv`、次に `PATH` の `priorwork` |
| `priorwork.python` | （空） | `.venv` を作るときの Python。空なら `python3`（Windows では `py -3`） |
| `priorwork.autoAdvance` | `true` | 採否を決めたら次の未選別の論文に進む |

## 外部に送るもの

検索クエリと DOI を Semantic Scholar・OpenAlex に送ります。Zotero を設定した場合は、Zotero の
ライブラリを読みます（読み取りのみ）。それ以外はどこにも送りません。
